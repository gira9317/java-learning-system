## まずはここから

Webサイトを開くたびに数字の宛先を覚えるのは大変です。名前からIPアドレス等の情報を調べる仕組みがDNSです。連絡先の名前から電話番号を調べる場面に似ています。

### 最初に覚える4つの言葉

#### DNS

名前に対応する宛先等の情報を調べる仕組み。

**具体例：** サイト名から接続先IPを調べる。

#### ドメイン名

ネットワーク上で使う名前。

**具体例：** example.comという名前を使う。

#### Aレコード

名前にIPv4アドレスを対応させる情報。

**具体例：** サイトの名前とIPを登録する。

#### キャッシュ

取得済みの情報を一時的に覚える仕組み。

**具体例：** 前に調べた宛先をしばらく再利用する。

### この講義の読み方

まず上の意味と具体例を確認し、下の4択に挑戦しましょう。詳しい仕組みやコードは「詳しい説明」、発展した内容は「Option」で後から読めます。1回で全てを暗記する必要はありません。

## DNS とは

**Domain Name System** の略で、`www.example.com` のような **ドメイン名** を、`203.0.113.10` のような **IP アドレス** に変換する仕組みです。人は覚えやすい名前を使い、機械は IP アドレスで通信するための「インターネットの電話帳」です。

（このページの IP アドレスは、説明用に予約された例のアドレスです。）

## ドメイン名の構造

右から左へ、大きな区分から小さな区分の順に並んでいます。

```text
www . example . co . jp .
 │       │       │    │  └ ルート
 │       │       │    └ トップレベルドメイン（TLD）: jp
 │       │       └ 第 2 レベル: co（企業）
 │       └ 組織のドメイン: example
 └ ホスト名: www
```

## 名前解決の流れ

ブラウザに `www.example.com` を入力したとき:

1. PC は、まず自分のキャッシュや hosts ファイルを確認する
2. なければ、設定された **DNS キャッシュサーバー**（社内やプロバイダーのもの）に問い合わせる
3. キャッシュサーバーは、知らなければ **権威 DNS サーバー** を順にたどる
   - ルートサーバー →「com のことは、このサーバーへ」
   - com のサーバー →「example.com のことは、このサーバーへ」
   - example.com のサーバー →「www.example.com は 203.0.113.10」
4. キャッシュサーバーは結果を一定時間（**TTL**）覚えておき、PC に答える
5. PC は得た IP アドレスに接続する

## 主なレコード

権威 DNS サーバーには、ドメインの情報が **レコード** として登録されています。

| レコード | 内容 | 例 |
|---|---|---|
| A | ドメイン名 → IPv4 アドレス | `www.example.com → 203.0.113.10` |
| AAAA | ドメイン名 → IPv6 アドレス | |
| CNAME | 別名（別のドメイン名を指す） | `blog.example.com → example.github.io` |
| MX | そのドメインのメールを受け取るサーバー | `example.com → mail.example.com` |
| TXT | 任意の文字列。メールの送信元の認証（SPF など）に使う | |
| NS | そのドメインを管理する DNS サーバー | |

## 確認コマンド

```text
nslookup www.example.com
nslookup -type=mx example.com
```

## hosts ファイル

DNS に問い合わせる前に参照される、PC の中の名前と IP アドレスの対応表です（Windows では `C:\Windows\System32\drivers\etc\hosts`）。開発中に、本番と同じ名前でテスト用のサーバーに向けたいときなどに使います。

## DNS とトラブル

- **「IP アドレスでは接続できるのに、名前ではできない」** → DNS の設定や名前解決を疑う
- **DNS を変更しても反映されない** → TTL の間はキャッシュの古い情報が使われる
- **DNS の情報が書き換えられると**、偽のサイトに誘導される危険がある（DNS キャッシュポイズニング）。HTTPS の証明書の確認が、その対策の 1 つになる

## ポイント

- DNS はドメイン名を IP アドレスに変換する
- キャッシュサーバーが権威サーバーを順にたどり、結果を TTL の間覚えておく
- A・CNAME・MX は特によく使うレコード

### 問5【応用】

設定変更後もしばらく古い宛先へ行く理由の候補は？

#### 選択肢

- A. 全てのソフトが消えた
- B. 必ず写真が壊れている

- D. 画面が暗い

#### 解答・解説

正解: C

名前の情報を一時的に覚えている場所があり、更新の反映に時間がかかることがあります。

## Option：名前の変更には準備期間がある

切り替え直前にTTLを下げても、既に長いTTLで保存されたキャッシュには直ちに効きません。移行前から旧情報の寿命を考え、旧サーバーを残す期間も設計します。

**やってみよう：** サーバー移転について、準備・切り替え・確認・切り戻しの順を時系列で考えてみましょう。
