## OSI 参照モデルとは

ネットワーク通信の機能を、**7 つの層（レイヤー）** に分けて整理したモデルです。各層は決まった役割だけを担い、すぐ下の層の機能を使って、すぐ上の層に機能を提供します。

層に分けることで、「Wi-Fi を有線 LAN に変えても、ブラウザやアプリは変えなくてよい」のように、ある層の変更がほかの層に影響しにくくなります。

## 7 つの層

| 層 | 名前 | 役割 | 代表例 | データの単位 |
|---|---|---|---|---|
| 7 | アプリケーション層 | アプリケーションごとの通信の決まり | HTTP、SMTP、FTP、DNS | メッセージ |
| 6 | プレゼンテーション層 | データの表現形式（文字コード、圧縮、暗号化） | TLS（の一部）、JPEG | |
| 5 | セッション層 | 通信の開始から終了までの管理 | | |
| 4 | トランスポート層 | 通信の信頼性、アプリケーションの識別（ポート） | TCP、UDP | セグメント |
| 3 | ネットワーク層 | 異なるネットワークをまたいだ宛先までの経路 | IP、ICMP | パケット |
| 2 | データリンク層 | 同じネットワーク内の隣の機器との通信 | Ethernet、Wi-Fi | フレーム |
| 1 | 物理層 | 電気信号・光・電波への変換 | LAN ケーブル、光ファイバー | ビット |

覚え方の例（上から）: 「アプリ・プレゼン・セッション・トランスポート・ネットワーク・データリンク・物理」

## カプセル化

送信側では、上の層から下の層へ渡すたびに、その層の情報（**ヘッダー**）が付け加えられます。受信側では、下の層から順にヘッダーを外して上へ渡します。

```text
[HTTP のデータ]
[TCP ヘッダー][HTTP のデータ]
[IP ヘッダー][TCP ヘッダー][HTTP のデータ]
[Ethernet ヘッダー][IP ヘッダー][TCP ヘッダー][HTTP のデータ][FCS]
```

手紙を封筒に入れ、さらに大きな封筒に入れて送るイメージです。

## TCP/IP モデルとの対応

実際のインターネットは、TCP/IP の 4 層モデルで動いています。OSI 参照モデルは、仕組みを説明・整理するための「ものさし」として使われます。

| TCP/IP モデル | OSI 参照モデル |
|---|---|
| アプリケーション層 | 7・6・5 層 |
| トランスポート層 | 4 層 |
| インターネット層 | 3 層 |
| ネットワークインターフェース層 | 2・1 層 |

## トラブルの切り分けに使う

通信できないときは、下の層から順に確かめると原因を絞り込めます。

1. 物理層: ケーブルは挿さっているか、Wi-Fi はつながっているか
2. ネットワーク層: IP アドレスは正しいか、`ping` は通るか
3. トランスポート層: ポートは開いているか、ファイアウォールで止められていないか
4. アプリケーション層: URL や認証情報は正しいか

## ポイント

- 通信の機能を 7 層に分け、各層は自分の役割だけを担う
- 送るときは上から下へヘッダーを付け、受け取るときは外す
- 実際は TCP/IP の 4 層。OSI はトラブルの切り分けにも役立つ

> **確認しよう**
>
> - HTTP、TCP、IP、Ethernet は、それぞれ何層でしょうか。
> - `ping` は通るのに Web ページが開けないとき、どの層を疑えばよいでしょうか。
