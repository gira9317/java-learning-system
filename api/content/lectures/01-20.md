## 文字コードとは

文字とバイト列（数値）の対応表です。コンピューターは文字を数値で記憶するため、「どの文字を何番にするか」を決めておく必要があります。

- **文字集合**: 扱う文字の一覧と、それぞれの番号（例: Unicode）
- **符号化方式**: 番号を、どんなバイト列で表すか（例: UTF-8）

## 代表的な文字コード

| 文字コード | 特徴 |
|---|---|
| ASCII | 英数字と記号の 128 文字。7 ビット |
| Shift_JIS（SJIS） | 日本語の文字コード。古い Windows や Excel の CSV で使われる |
| EUC-JP | 日本語の文字コード。古い UNIX 系で使われた |
| UTF-8 | Unicode の符号化方式。世界中の文字を扱える。Web や現在の標準 |
| UTF-16 | Unicode の符号化方式。Java の `char` や `String` の内部表現 |

Windows で「ANSI」や「MS932」「CP932」と表示されるものは、Shift_JIS を拡張したものです。

## UTF-8 のバイト数

UTF-8 は文字によって **1〜4 バイト** を使い分けます。

| 文字 | バイト数 | 例 |
|---|---|---|
| ASCII（英数字） | 1 | `A` → `41` |
| ラテン文字の一部、ギリシャ文字など | 2 | `é` → `C3 A9` |
| ひらがな・漢字の多く | 3 | `あ` → `E3 81 82` |
| 絵文字、一部の漢字 | 4 | `😀` → `F0 9F 98 80` |

## 文字化け

書いたときと **違う文字コードで読む** と、文字化けが起きます。

```java
byte[] utf8 = "日本語".getBytes(StandardCharsets.UTF_8);
String wrong = new String(utf8, Charset.forName("Shift_JIS"));
System.out.println(wrong); // 譌･譛ｬ隱? のように化ける
```

よくある原因:

- Excel で保存した CSV（Shift_JIS）を、UTF-8 として読む
- ファイルは UTF-8 なのに、コンソールが別の文字コードで表示している
- DB の文字コードと、アプリの接続設定が違う

## 改行コードと BOM

- **改行コード**: Windows は `CRLF`（`\r\n`）、Linux・macOS は `LF`（`\n`）
- **BOM**: UTF-8 のファイルの先頭に付くことがある `EF BB BF` の 3 バイト。付いていると、読み込んだ最初の行に見えない文字が混ざることがある

## Java での注意点

- 入出力では **文字コードを必ず明示する**（`StandardCharsets.UTF_8`）
- `String.length()` は文字数ではなく UTF-16 の単位数。絵文字は 2 と数えられる

```java
System.out.println("😀".length());                       // 2
System.out.println("😀".codePointCount(0, "😀".length())); // 1
```

## ポイント

- 文字コードは文字と数値の対応表。今の標準は UTF-8
- 書いたときと読むときの文字コードをそろえる
- 日本語は UTF-8 で多くが 3 バイト、Shift_JIS で 2 バイト
