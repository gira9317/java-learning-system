## まずはここから

この講義はJavaの全体地図です。ここで全てを使いこなす必要はありません。まず『値を覚える・順番に動く・条件で分ける・繰り返す』を押さえ、クラスやStreamは後から戻って読みましょう。

### 最初に覚える4つの言葉

#### 変数

値に名前を付けて扱う仕組み。

**具体例：** scoreという名前で点数を覚える。

#### メソッド

まとまった処理に名前を付けたもの。

**具体例：** 合計する処理を何度も呼ぶ。

#### クラス

データと処理のまとまりを定義するもの。

**具体例：** 社員の名前と操作をまとめる。

#### 例外

通常の処理を続けられない状況を伝える仕組み。

**具体例：** 数値にできない文字を変換しようとする。

## この講義の範囲

Java で業務プログラムを書くための主要な要素を、ひと通り確認します。それぞれの詳しい書き方は「コード演習」で手を動かして身につけます。

| テーマ | 一言でいうと |
|---|---|
| 基本文法 | 変数・型・演算・分岐・繰り返し・配列 |
| メソッド | 処理に名前を付けて、まとめて再利用する |
| オブジェクト指向 | データと処理を「クラス」にまとめて設計する |
| ラムダ式 | 処理そのものを値として渡す |
| Stream API | コレクションの絞り込み・変換・集計を宣言的に書く |
| 例外 | エラーを検出して、適切に処理する |
| スレッド | 複数の処理を同時に進める |
| サーブレット | Web のリクエストを受けて応答を返す |

## 基本文法

```java
public class Main {
    public static void main(String[] args) {
        int[] scores = {80, 55, 92};
        int passed = 0;
        for (int s : scores) {
            if (s >= 60) {
                passed++;
            }
        }
        System.out.println("合格者: " + passed + " 人");
    }
}
```

- プログラムは `main` メソッドから始まる
- 文の終わりに `;`、ブロックは `{ }`
- 配列は長さが固定。長さが変わるなら `List`（`ArrayList`）を使う

## メソッド

```java
static int add(int a, int b) {   // 戻り値の型 メソッド名(引数)
    return a + b;
}

int total = add(3, 4); // 7
```

- 1 つのメソッドには 1 つの仕事をさせ、名前で何をするかがわかるようにする
- 同じ名前で引数の型や数が違うメソッドを定義できる（**オーバーロード**）

## オブジェクト指向

**クラス** は設計図、**インスタンス（オブジェクト）** は設計図から作った実物です。

```java
public class Employee {
    private final String name;   // フィールド（データ）
    private int salary;

    public Employee(String name, int salary) { // コンストラクタ
        this.name = name;
        this.salary = salary;
    }

    public void raise(int amount) {  // メソッド（振る舞い）
        if (amount <= 0) throw new IllegalArgumentException("昇給額は正の数");
        salary += amount;
    }

    public String getName() { return name; }
    public int getSalary() { return salary; }
}

Employee e = new Employee("山田", 250_000);
e.raise(10_000);
```

オブジェクト指向の 3 つの柱:

| 柱 | 内容 | Java での手段 |
|---|---|---|
| カプセル化 | データを隠し、決められた操作だけを公開する | `private` フィールド、メソッド |
| 継承 | 既存のクラスの性質を引き継いで新しいクラスを作る | `extends` |
| ポリモーフィズム（多態性） | 同じ呼び方で、型ごとに違う動きをさせる | オーバーライド、`interface` |

```java
interface Shape {
    double area();
}
record Circle(double r) implements Shape {
    public double area() { return Math.PI * r * r; }
}
record Square(double side) implements Shape {
    public double area() { return side * side; }
}

List<Shape> shapes = List.of(new Circle(1), new Square(2));
for (Shape s : shapes) {
    System.out.println(s.area()); // 型ごとの area() が呼ばれる
}
```

継承は便利ですが、関係が複雑になりやすいため、まず `interface` と組み合わせ（has-a）で設計できないかを考えます。

## ラムダ式

「処理」を値として、メソッドに渡せます。

```java
List<String> names = new ArrayList<>(List.of("Sato", "Ito", "Suzuki"));

// 文字数の短い順に並べる
names.sort((a, b) -> a.length() - b.length());

// メソッド参照
names.forEach(System.out::println);
```

ラムダ式は、抽象メソッドが 1 つだけのインターフェース（**関数型インターフェース**: `Comparator`、`Runnable`、`Function`、`Predicate` など）の代わりに書けます。

## Stream API

コレクションのデータを「流れ」として、絞り込み・変換・集計をつなげて書きます。

```java
List<Employee> employees = ...;

// 給与 30 万円以上の社員の名前を、給与の高い順に
List<String> names = employees.stream()
        .filter(e -> e.getSalary() >= 300_000)
        .sorted(Comparator.comparingInt(Employee::getSalary).reversed())
        .map(Employee::getName)
        .toList();

// 平均給与
double avg = employees.stream()
        .mapToInt(Employee::getSalary)
        .average()
        .orElse(0);
```

| 操作 | 種類 | 内容 |
|---|---|---|
| `filter` | 中間操作 | 条件に合うものだけ残す |
| `map` | 中間操作 | 別の値に変換する |
| `sorted` | 中間操作 | 並べ替える |
| `toList` / `collect` | 終端操作 | 結果をまとめる |
| `count` / `sum` / `average` | 終端操作 | 集計する |

終端操作を呼ぶまで、中間操作は実行されません。

## 例外

実行中に起きた異常を、**例外** として投げて（throw）、受け止めて（catch）処理します。

```java
try {
    int n = Integer.parseInt(input);
    System.out.println(100 / n);
} catch (NumberFormatException e) {
    System.out.println("数値を入力してください");
} catch (ArithmeticException e) {
    System.out.println("0 では割れません");
} finally {
    System.out.println("終了"); // 例外があってもなくても実行される
}
```

| 種類 | 内容 | 例 |
|---|---|---|
| チェック例外 | 処理（catch か throws）が強制される。外部要因で起きうる | `IOException`、`SQLException` |
| 非チェック例外 | 処理は強制されない。多くはプログラムの誤り | `NullPointerException`、`IllegalArgumentException` |
| エラー | 回復できない深刻な問題 | `OutOfMemoryError` |

例外を catch して **何もしない（握りつぶす）** のは避けます。少なくともログに残します。

## スレッド

1 つのプログラムの中で、複数の処理を同時に進める仕組みです。重い処理を裏で行う、複数のリクエストを同時に処理する、などで使います。

```java
ExecutorService pool = Executors.newFixedThreadPool(4);
Future<Integer> result = pool.submit(() -> heavyCalculation());
// 別の処理を進める …
System.out.println(result.get()); // 結果を待って受け取る
pool.shutdown();
```

複数のスレッドが同じデータを同時に書き換えると、値が壊れることがあります（**競合状態**）。共有するデータは、`synchronized`、`AtomicInteger`、スレッドセーフなコレクション（`ConcurrentHashMap` など）で守ります。

## サーブレット

Web サーバー（Tomcat などのサーブレットコンテナ）の上で動き、HTTP のリクエストを受けて、レスポンスを返す Java のクラスです。

```java
@WebServlet("/hello")
public class HelloServlet extends HttpServlet {
    @Override
    protected void doGet(HttpServletRequest req, HttpServletResponse resp) throws IOException {
        String name = req.getParameter("name");
        resp.setContentType("text/plain; charset=UTF-8");
        resp.getWriter().println("こんにちは、" + name + " さん");
    }
}
```

- GET は `doGet`、POST は `doPost` で処理する
- セッションは `req.getSession()` で扱う
- 現在の業務開発では、サーブレットの上に作られた **Spring Boot** などのフレームワークを使うことが多い。仕組みを知っておくと、フレームワークの動きも理解しやすくなる

（HTTP、GET / POST、セッションは第 3 章で詳しく扱います。）

## ポイント

- メソッドで処理を分け、クラスでデータと処理をまとめる
- カプセル化・継承・ポリモーフィズムを使い分ける
- ラムダ式と Stream API で、コレクションの処理を短く書ける
- 例外は握りつぶさない。スレッドは共有データに注意する
- サーブレットは Web アプリケーションの土台

## Option：Streamの見た目より副作用の管理

Streamはデータ変換を組み立てやすくしますが、外部の可変状態を書き換える処理を混ぜると、順番や並列実行に依存しやすくなります。まず戻り値で結果を組み立てる設計を考えましょう。

**やってみよう：** filter・map・collectで結果を作る処理と、forEachで外側のListへ追加する処理の違いを説明してみましょう。
