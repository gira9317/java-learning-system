## まずはここから

アクセス制御は、『誰が、何をしてよいか』を決める仕組みです。会社の部屋に入れる人を分けるのと似ています。全員に全て許すのではなく、必要な範囲だけ許すことが基本です。

### 最初に覚える4つの言葉

#### アクセス制御

利用できる対象や操作を制限すること。

**具体例：** 管理者だけが社員情報を変更できる。

#### ファイアウォール

通信を条件に応じて通したり止めたりする仕組み。

**具体例：** 不要な外部接続を止める。

#### 権限

許可された操作の範囲。

**具体例：** 読むことはできるが変更はできない。

#### 最小権限

必要な分だけ許可する考え方。

**具体例：** 担当者に必要な対象だけ開放する。

### この講義の読み方

まず上の意味と具体例を確認し、下の4択に挑戦しましょう。詳しい仕組みやコードは「詳しい説明」、発展した内容は「Option」で後から読めます。1回で全てを暗記する必要はありません。

## アクセスコントロールとは

「**誰が（どこから）、何に、どんな操作をしてよいか**」を制御することです。ネットワークでは、許可された通信だけを通し、それ以外を止めることで、不正なアクセスや情報漏えいを防ぎます。

## ファイアウォール

ネットワークの境界に置き、ルールに従って通信を許可・拒否します。

| 方式 | 見るもの | 内容 |
|---|---|---|
| パケットフィルタリング | 送信元・宛先の IP アドレス、ポート番号、プロトコル | 基本的な方式 |
| ステートフルインスペクション | 上に加え、通信の状態 | 社内から始めた通信の「返り」だけを通す |
| アプリケーションゲートウェイ（WAF など） | 通信の中身 | HTTP の中の攻撃パターンなどを止める |

ルールの例:

| 順番 | 送信元 | 宛先 | ポート | 動作 |
|---|---|---|---|---|
| 1 | すべて | Web サーバー | 443 | 許可 |
| 2 | 管理用ネットワーク | Web サーバー | 22 | 許可 |
| 3 | すべて | すべて | すべて | 拒否 |

ルールは上から順に評価されます。「必要なものだけ許可し、最後にすべて拒否」が基本です（**ホワイトリスト方式**）。

## ACL（アクセス制御リスト）

ルーターやスイッチ、ファイル、データベースなどに設定する「許可・拒否の一覧」です。ネットワーク機器では、上のファイアウォールのルールと同じ考え方で通信を制御します。

## DMZ

インターネットに公開するサーバー（Web サーバー、メールサーバーなど）を置く、**社内ネットワークとは分けた区画** です。

```text
インターネット ── ファイアウォール ── DMZ（公開サーバー）
                         │
                    社内ネットワーク（社員の PC、社内システム）
```

公開サーバーが乗っ取られても、社内ネットワークへの侵入を防ぎやすくなります。

## 最小権限の原則

**必要な人に、必要な権限だけを、必要な期間だけ** 与えるという考え方です。ネットワークだけでなく、OS のユーザー、データベース、アプリケーションの権限にも当てはまります。

- アプリケーションが使う DB ユーザーには、必要なテーブルの必要な操作だけを許可する
- 管理用の SSH は、管理用のネットワークからだけ許可する
- 異動や退職したら、すぐに権限を外す

## アプリケーションでのアクセス制御

システムの中でも、利用者ごとに操作を制御します。

- **認証**: 本人であることを確かめる（第 5 章）
- **認可**: 認証した利用者に、何を許可するかを決める（例: 研修担当者だけが提出をレビューできる）

画面でボタンを隠すだけでは不十分です。**サーバー側で必ず権限を確認** します。

## ポイント

- 必要な通信だけを許可し、それ以外は拒否する
- 公開サーバーは DMZ に置き、社内ネットワークと分ける
- 権限は最小限に。アプリケーションでは必ずサーバー側で確認する

## Option：許可した理由も管理する

アクセスルールは追加だけ続けると、不要な権限が残ります。目的、対象、承認者、有効期限を記録し、定期的に見直すと管理しやすくなります。

**やってみよう：** Web→API→DBの各接続について、送信元・宛先・ポート・用途を最低限の表にしてみましょう。
