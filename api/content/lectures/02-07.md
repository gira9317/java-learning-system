## パケットキャプチャとは

ネットワークを流れるパケットを取り込み（キャプチャし）、中身を見て分析することです。

- 通信できない原因を調べる（どこまで届いているか、どんな応答が返っているか）
- 遅い原因を調べる（再送が多い、応答に時間がかかっている）
- プロトコルの仕組みを実際に見て学ぶ

## 代表的なツール

| ツール | 内容 |
|---|---|
| Wireshark | 画面で操作する、最も広く使われているツール |
| tcpdump | Linux などのコマンドラインで使う。サーバー上での取得に向く |
| ブラウザの開発者ツール（Network タブ） | ブラウザが送受信した HTTP 通信を見る |

## Wireshark の基本

1. キャプチャするネットワークインターフェース（有線、Wi-Fi など）を選ぶ
2. キャプチャを開始し、調べたい操作を行い、停止する
3. **フィルター** で、見たいパケットだけに絞る

| フィルターの例 | 意味 |
|---|---|
| `ip.addr == 192.168.1.10` | この IP アドレスが関わる通信 |
| `tcp.port == 443` | ポート 443 の通信 |
| `http` | HTTP の通信 |
| `dns` | DNS の通信 |
| `tcp.flags.syn == 1` | TCP の接続開始のパケット |

1 つのパケットを選ぶと、OSI 参照モデルの層ごとに、ヘッダーの中身（MAC アドレス、IP アドレス、ポート番号など）が表示されます。

## 見えるもの・見えないもの

- **HTTP** など暗号化されていない通信は、送受信した内容（パスワードを含む）がそのまま見える
- **HTTPS** の通信は、宛先の IP アドレスやポートは見えるが、中身は暗号化されていて読めない

暗号化していない通信は、同じネットワークにいる人に盗み見られる可能性がある、ということです。これが、通信を HTTPS にする理由の 1 つです。

## ブラウザの開発者ツールで HTTP を見る

Web アプリケーションの開発では、まずブラウザの開発者ツール（F12）の **Network** タブを使います。

- どの URL に、どのメソッド（GET / POST）で送ったか
- ステータスコード（200、404、500 など）
- 送ったヘッダーとデータ、返ってきたデータ
- かかった時間

画面の不具合が「送っていない」のか「サーバーがエラーを返した」のかを切り分けられます。

## 注意すること

パケットキャプチャは、ほかの人の通信も見えてしまう強力な手段です。

- **許可されたネットワーク・機器でだけ** 行う。無断でほかの人の通信をキャプチャするのは、法律や社内規程に違反するおそれがある
- 取得したファイルには、パスワードや個人情報が含まれることがある。扱いに注意し、不要になったら削除する

## ポイント

- パケットキャプチャで、通信の実際の中身を確かめられる
- Wireshark ではフィルターで絞り込み、層ごとに中身を見る
- 暗号化していない通信は中身がそのまま見える
- 必ず許可を得た範囲で行う

> **確認しよう**
>
> - Web ページを開いたときの、DNS の問い合わせと TCP の 3 ウェイハンドシェイクを、どんなフィルターで探せるでしょうか。
> - ログイン画面が HTTP だと、なぜ危険なのでしょうか。
