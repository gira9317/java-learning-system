## まずはここから

条件を2つ合わせたいときに使うのが論理演算です。『会員で、しかも購入額が一定以上』と『会員か、またはクーポンがある』では、条件のつなぎ方が違います。

### 最初に覚える4つの言葉

#### AND（&&）

両方の条件が成り立つこと。

**具体例：** 会員で、しかも18歳以上である。

#### OR（||）

少なくとも片方の条件が成り立つこと。

**具体例：** 現金かカードのどちらかを使える。

#### NOT（!）

条件の結果を逆にすること。

**具体例：** ログイン済みではないと判定する。

#### true／false

条件が成り立つ／成り立たないという値。

**具体例：** 雨が降っているという条件の結果を表す。

### この講義の読み方

まず上の意味と具体例を確認し、下の4択に挑戦しましょう。詳しい仕組みやコードは「詳しい説明」、発展した内容は「Option」で後から読めます。1回で全てを暗記する必要はありません。

## 論理演算とは

真（true）と偽（false）を組み合わせて、新しい真偽値を作る演算です。複数の条件をまとめるときに使います。

| 演算 | Java | 意味 |
|---|---|---|
| 論理積（AND） | `&&` | 両方が真なら真 |
| 論理和（OR） | `\|\|` | どちらかが真なら真 |
| 否定（NOT） | `!` | 真と偽を反転する |

## 真理値表

| A | B | A && B | A \|\| B | !A |
|---|---|---|---|---|
| true | true | true | true | false |
| true | false | false | true | false |
| false | true | false | true | true |
| false | false | false | false | true |

## 使い方の例

```java
int age = 25;
boolean member = true;

// 20 歳以上 かつ 会員
if (age >= 20 && member) { ... }

// 土曜 または 日曜
if (day.equals("土") || day.equals("日")) { ... }

// 会員でない
if (!member) { ... }
```

範囲の判定は、`&&` で 2 つの比較をつなぎます。数学のように `0 <= x <= 100` とは書けません。

```java
if (0 <= x && x <= 100) { ... }
```

## 短絡評価（ショートサーキット）

`&&` は左が偽なら、`||` は左が真なら、**右側を評価しません**。結果が確定しているからです。これを利用すると、エラーを防げます。

```java
// name が null のときは、右の name.isEmpty() を実行しない
if (name != null && !name.isEmpty()) { ... }
```

順番を逆にすると、`name` が `null` のときに `NullPointerException` が発生します。

## ド・モルガンの法則

否定を分配するときは、AND と OR が入れ替わります。

- `!(A && B)` は `!A || !B` と同じ
- `!(A || B)` は `!A && !B` と同じ

```java
// 「0 以上 100 以下」ではない
!(0 <= x && x <= 100)
// は、次と同じ
x < 0 || 100 < x
```

条件を読みやすく書き直すときに役立ちます。

## ポイント

- `&&` は両方、`||` はどちらか、`!` は反転
- 範囲は `a <= x && x <= b` と書く
- 短絡評価を利用して、null チェックを先に書く
- 否定を外すと AND と OR が入れ替わる

### 問1

「両方の条件が成り立つこと」に当てはまるものはどれですか。

#### 選択肢

- A. NOT（!）
- B. AND（&&）
- C. OR（||）

正解: B

### 問5【応用】

true && falseの結果は？

#### 選択肢

- A. 条件を判断できない
- B. 2
- C. false
- D. true

#### 解答・解説

正解: C

ANDは両方がtrueのときだけtrueになります。

## Option：短絡評価と副作用

条件式の中で値の更新や外部通信をすると、短絡評価によって実行される場合とされない場合ができます。条件はなるべく判定に専念させ、必要な処理は別の文へ分けると読みやすくなります。

**やってみよう：** false && check()でcheckが呼ばれないことを、ログを出す小さなプログラムで確認してみましょう。
