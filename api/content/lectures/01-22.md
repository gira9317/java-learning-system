## まずはここから

ハッシュ値は、データから決まった計算で作る『照合用の目印』のような値です。同じデータなら同じ値になります。暗号と違い、元の文章へ戻して読むための仕組みではありません。

### 最初に覚える4つの言葉

#### ハッシュ値

データから計算する照合用の値。

**具体例：** ダウンロード前後のファイルを比べる。

#### ハッシュ関数

ハッシュ値を計算するルール。

**具体例：** 同じデータから同じ目印を作る。

#### ソルト

パスワード等の計算へ加える個別の値。

**具体例：** 同じパスワードでも保存値を変える。

#### チェックサム

データの誤り検出等に使う確認値。

**具体例：** ファイルが壊れていないか確認する。

## ハッシュ関数とハッシュ値

**ハッシュ関数** は、任意の長さのデータから、**決まった長さの値（ハッシュ値）** を作る関数です。

```text
SHA-256("hello")  → 2cf24dba5fb0a30e26e83b2ac5b9e29e1b161e5c1fa7425e73043362938b9824
SHA-256("hello!") → ce06092fb948d9ffac7d1a376e404b26b7575bcc11ee05a4615fef4fec3a308b
```

暗号に使われるハッシュ関数には、次の性質があります。

| 性質 | 内容 |
|---|---|
| 同じ入力なら同じ値 | 何度計算しても同じハッシュ値になる |
| 一方向性 | ハッシュ値から元のデータを求められない |
| 少しの違いで大きく変わる | 1 文字違うだけで、まったく別の値になる |
| 衝突しにくい | 違うデータから同じハッシュ値を作るのが極めて難しい |

## 主なハッシュ関数

| 名前 | 長さ | 状況 |
|---|---|---|
| MD5 | 128 ビット | 衝突が見つかっており、安全性が必要な用途には使わない |
| SHA-1 | 160 ビット | 同上 |
| SHA-256 | 256 ビット | 現在広く使われる |

## 使い道

### 改ざん・破損の検出

ダウンロードしたファイルのハッシュ値を、配布元が公開している値と比べれば、途中で壊れたり書き換えられたりしていないかがわかります。

```bat
certutil -hashfile setup.zip SHA256
```

### パスワードの保存

パスワードは平文でも暗号化でもなく、**ハッシュ化** して保存します。照合するときは、入力されたパスワードをハッシュ化して比べます。

ただし SHA-256 をそのまま使うと、高速なため総当たりで破られやすくなります。パスワードには、**ソルト**（ユーザーごとのランダムな値）を加え、わざと計算を重くした専用の方式（**bcrypt**、**Argon2**、PBKDF2 など）を使います。このシステムも Argon2 を使っています。

### データの比較・検索

大きなデータを、短いハッシュ値で比べたり探したりできます（Java の `HashMap` も、キーのハッシュ値で置き場所を決めています）。

## チェックサム

データの **誤り（破損）を検出する** ための値です。送信側で計算して付け、受信側で計算し直して一致するか確かめます。

| 方式 | 例 |
|---|---|
| パリティビット | 1 の数が偶数か奇数かを示す 1 ビット |
| CRC | ZIP、Ethernet などで使われる |
| チェックディジット | クレジットカード番号やバーコードの最後の 1 桁 |

チェックサムは **偶然の誤り** を見つけるためのもので、悪意のある改ざんには、暗号用のハッシュ関数や署名を使います。

## Java で SHA-256 を計算する

```java
import java.security.MessageDigest;
import java.nio.charset.StandardCharsets;
import java.util.HexFormat;

MessageDigest md = MessageDigest.getInstance("SHA-256");
byte[] hash = md.digest("hello".getBytes(StandardCharsets.UTF_8));
System.out.println(HexFormat.of().formatHex(hash));
```

## ポイント

- ハッシュは一方向。元に戻せない
- 改ざん検出には SHA-256、パスワードにはソルト付きの専用方式
- チェックサムは偶然の誤りの検出用

### 問5【応用】

同じデータへ同じハッシュ関数を使うと？

#### 選択肢

- A. 元データを削除する
- B. 同じハッシュ値になる
- C. 毎回必ず違う値になる
- D. 必ず元データより長くなる

#### 解答・解説

正解: B

同じ入力と同じ方式なら同じ値です。ただし、同じ値なら必ず同じデータという保証ではありません。

## Option：ハッシュの一致と信頼できる照合先

配布ファイルと同じ場所にあるハッシュ値も同時に改ざんされれば、照合だけでは不正を検知できません。信頼できる別経路やデジタル署名も検討します。

**やってみよう：** ファイル破損の検出と、配布元の真正性の確認を、それぞれどの仕組みで行うか整理してみましょう。
