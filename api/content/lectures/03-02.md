## まずはここから

情報を見るお願いと、情報を登録するお願いは区別します。HTTPでは、その操作の種類をメソッドで表します。最初は検索するGETと、登録等に使うPOSTを分けて覚えましょう。

### 最初に覚える4つの言葉

#### GET

情報を取得する時に使うメソッド。

**具体例：** 商品の一覧を表示する。

#### POST

データ送信や処理の依頼に使うメソッド。

**具体例：** 購入する注文を送る。

#### クエリ文字列

URLへ付ける条件等の文字列。

**具体例：** 検索するキーワードを渡す。

#### 二重送信

同じ操作の要求を重複して送ること。

**具体例：** 登録を2回送り同じデータが増える。

### この講義の読み方

まず上の意味と具体例を確認し、下の4択に挑戦しましょう。詳しい仕組みやコードは「詳しい説明」、発展した内容は「Option」で後から読めます。1回で全てを暗記する必要はありません。

## GET と POST

HTML のフォームや Web API で最もよく使う、2 つの HTTP メソッドです。

| | GET | POST |
|---|---|---|
| 目的 | データを **取得** する | データを **送って処理させる**（登録、更新など） |
| データの送り方 | URL のクエリ文字列 | リクエストのボディ |
| URL に表示される | される | されない |
| ブックマーク・共有 | できる | できない |
| ブラウザの履歴・サーバーのログ | URL ごと残る | ボディは通常残らない |
| 送れる量 | URL の長さの上限がある | 大きなデータ・ファイルも送れる |
| 繰り返したとき | 何度実行しても結果は同じであるべき | 繰り返すと二重に登録されうる |

## GET の例

```http
GET /search?keyword=java&page=2 HTTP/1.1
Host: www.example.com
```

```html
<form action="/search" method="get">
  <input name="keyword">
  <button>検索</button>
</form>
```

検索条件のように、URL を共有したり、ブックマークしたりしたいものに向いています。

## POST の例

```http
POST /members HTTP/1.1
Host: www.example.com
Content-Type: application/x-www-form-urlencoded

name=%E5%B1%B1%E7%94%B0&dept=dev
```

```html
<form action="/members" method="post">
  <input name="name">
  <button>登録</button>
</form>
```

フォームから送る場合、ボディは `application/x-www-form-urlencoded`（`key=value&...` を URL エンコードした形）、ファイルを含む場合は `multipart/form-data`、Web API では `application/json` がよく使われます。

## 使い分けのルール

- **データを変更する操作には、GET を使わない**
  - GET はリンクのクリック、ブラウザの先読み、検索エンジンの巡回などで、意図せず送られることがある
  - 「`/delete?id=10` にアクセスすると削除される」という作りは危険
- **パスワードや個人情報は GET で送らない**
  - URL は履歴・ログ・共有したリンクに残る
- POST でも、HTTPS でなければ盗み見られる。**暗号化は HTTPS の役割**

## 安全・べき等

| 性質 | 意味 | 当てはまるメソッド |
|---|---|---|
| 安全 | サーバーの状態を変えない | GET、HEAD |
| べき等 | 何回実行しても、1 回実行したのと同じ結果になる | GET、PUT、DELETE |

POST はべき等ではないため、二重送信に注意します。

## 二重送信を防ぐ

「登録」ボタンを 2 回押したり、送信後にブラウザを再読み込みしたりすると、同じ POST が 2 回送られることがあります。

- 送信中はボタンを押せなくする
- **PRG パターン**: POST を処理したら、結果画面へ **リダイレクト**（302 / 303）し、結果画面は GET で表示する。再読み込みしても GET が繰り返されるだけになる

```text
ブラウザ ──POST /members──→ サーバー（登録する）
ブラウザ ←─303 Location: /members/42──
ブラウザ ──GET /members/42──→ サーバー（結果を表示）
```

## サーブレットでの受け取り

```java
// GET でも POST でも、パラメーターは同じ方法で取り出せる
String keyword = req.getParameter("keyword");
```

日本語を受け取るときは、文字コードを UTF-8 に設定しておきます（`req.setCharacterEncoding("UTF-8")`）。

## ポイント

- 取得は GET、変更は POST（など）。データを変える操作に GET を使わない
- 秘密の情報を URL に載せない
- POST は二重送信に注意し、PRG パターンで防ぐ

## Option：画面側の二重クリック対策だけでは足りない

ボタンの無効化は操作上の重複を減らしますが、通信の再試行や別のクライアントからの要求は防げません。重要な更新の一意性はサーバーとデータ設計でも守ります。

**やってみよう：** 注文送信後に返答だけ失われた状況で、利用者が安全に結果を確認できる流れを考えてみましょう。
