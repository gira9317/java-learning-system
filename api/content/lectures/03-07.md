## FTP とは

**File Transfer Protocol** の略で、ネットワークを通じてファイルを送受信するための、古くからあるプロトコルです。Web サーバーへのファイルのアップロードや、システム間のファイル連携に使われてきました。

## 仕組み

FTP は、**2 本の接続** を使います。

| 接続 | ポート | 役割 |
|---|---|---|
| 制御用 | 21 | ログイン、コマンド（一覧、取得、送信など）のやりとり |
| データ用 | 20 など | ファイルの中身や一覧の転送 |

データ用の接続のつなぎ方には 2 種類あります。

| モード | 内容 |
|---|---|
| アクティブモード | サーバーから、クライアントに向けて接続する。ファイアウォールで止められやすい |
| パッシブモード | クライアントから、サーバーが指定したポートに接続する。現在はこちらが一般的 |

## よく使うコマンド

```text
ftp ftp.example.com
ユーザー: user01
パスワード: ********
ftp> ls              （サーバーのファイル一覧）
ftp> cd upload       （サーバー側のフォルダを移動）
ftp> binary          （バイナリモードにする）
ftp> put data.csv    （送信＝アップロード）
ftp> get result.zip  （受信＝ダウンロード）
ftp> bye
```

### 転送モード

| モード | 内容 |
|---|---|
| アスキー（テキスト）モード | 改行コードを相手の OS に合わせて変換する |
| バイナリモード | 1 バイトも変えずに送る |

画像や ZIP をアスキーモードで送ると、ファイルが壊れます。迷ったら **バイナリモード** を使います。

## FTP の問題点

FTP は、**ユーザー名・パスワード・ファイルの中身をすべて暗号化せずに** 送ります。同じネットワークで通信をのぞかれると、パスワードを盗まれます（第 2 章「パケットキャプチャ」）。

そのため、現在は次のような安全な方式を使います。

| 方式 | 内容 |
|---|---|
| SFTP | SSH の上でファイルを転送する（ポート 22）。FTP とは別のプロトコル |
| FTPS | FTP の通信を TLS で暗号化したもの |
| SCP | SSH を使ってファイルをコピーする |
| HTTPS でのアップロード | Web 画面や API でファイルを送る |
| クラウドストレージ | Amazon S3 などの API を使う |

```text
sftp user01@server.example.com
sftp> put data.csv
```

## 業務での注意

- 新しく作るシステムでは、暗号化されていない FTP を使わない
- 既存のシステムとの連携で FTP が残っている場合は、閉じたネットワークの中だけで使う、SFTP に移行する計画を立てる、などを検討する
- 自動でファイルを送る場合は、パスワードではなく **SSH の鍵認証** を使い、鍵は厳重に管理する

## ポイント

- FTP は制御用（21）とデータ用の 2 本の接続を使う
- 画像や ZIP はバイナリモードで送る
- FTP は暗号化されないため、今は SFTP・FTPS などを使う

> **確認しよう**
>
> - FTP で送った ZIP ファイルが開けなくなったとき、何を疑いますか。
> - SFTP と FTPS の違いを説明してみましょう。
