## データベースとは

データを整理して保存し、検索・更新できるようにしたものです。管理するソフトウェアを **DBMS**（データベース管理システム）といいます。ファイルにデータを書くのと比べて、次の点が優れています。

- 大量のデータから、条件に合うものを速く探せる
- 複数の人やプログラムが同時に使っても、データが壊れない
- 決めたルール（必須、重複なし など）に反するデータを入れさせない
- 障害が起きても、データを回復できる

## RDB（リレーショナルデータベース）

データを **表（テーブル）** で表し、表と表を **関連（リレーション）** でつなぐデータベースです。業務システムで最も広く使われています。

代表的な製品: PostgreSQL、MySQL、Oracle Database、SQL Server

## 表の構成

**employees（社員）**

| id | name | dept_id | hired_on |
|---|---|---|---|
| 1 | 山田 | 10 | 2026-04-01 |
| 2 | 佐藤 | 20 | 2026-04-01 |
| 3 | 鈴木 | 10 | 2025-10-01 |

**departments（部署）**

| id | name |
|---|---|
| 10 | 開発部 |
| 20 | 営業部 |

| 用語 | 内容 |
|---|---|
| テーブル（表） | 同じ種類のデータの集まり |
| 行（レコード、タプル） | 1 件のデータ（社員 1 人） |
| 列（カラム、属性） | データの項目（氏名、部署） |
| 主キー（PK） | 行を一意に識別する列。重複も空（NULL）も許されない（例: `employees.id`） |
| 外部キー（FK） | ほかの表の主キーを参照する列（例: `employees.dept_id` → `departments.id`） |

外部キーがあると、存在しない部署の ID を社員に入れることを DB が防いでくれます（**参照整合性**）。

## 制約

表に入れられるデータのルールです。

| 制約 | 内容 |
|---|---|
| `PRIMARY KEY` | 主キー |
| `FOREIGN KEY` | 外部キー |
| `NOT NULL` | 空を許さない |
| `UNIQUE` | 重複を許さない |
| `CHECK` | 条件を満たす値だけ（例: `salary >= 0`） |
| `DEFAULT` | 値を指定しないときの初期値 |

## 正規化

データの **重複をなくし**、矛盾が起きないように表を分けることです。

正規化していない例（部署名が社員ごとに繰り返されている）:

| id | name | dept_name |
|---|---|---|
| 1 | 山田 | 開発部 |
| 3 | 鈴木 | 開発部 |

部署名を「開発本部」に変えるとき、すべての行を直す必要があり、直し漏れると矛盾します。部署を別の表に分け、ID で参照すれば、1 か所を直すだけで済みます。

| 段階 | 内容 |
|---|---|
| 第 1 正規形 | 1 つのセルに 1 つの値（繰り返しの列やカンマ区切りをなくす） |
| 第 2 正規形 | 主キーの一部だけで決まる列を、別の表に分ける |
| 第 3 正規形 | 主キー以外の列で決まる列を、別の表に分ける |

## トランザクション

複数の更新を **「すべて成功」か「すべて取り消し」** のひとまとまりとして扱う仕組みです。

```sql
BEGIN;
UPDATE accounts SET balance = balance - 10000 WHERE id = 1;
UPDATE accounts SET balance = balance + 10000 WHERE id = 2;
COMMIT;   -- どちらかが失敗したら ROLLBACK
```

トランザクションが守る性質を **ACID** といいます。

| 性質 | 内容 |
|---|---|
| 原子性（Atomicity） | 全部成功か、全部取り消しか |
| 一貫性（Consistency） | 制約に反する状態にならない |
| 独立性（Isolation） | 同時に実行しても互いに影響しない |
| 永続性（Durability） | 確定した結果は障害が起きても消えない |

## インデックス

本の索引のように、検索を速くするための仕組みです。よく検索の条件に使う列に作ります。ただし、作りすぎると登録・更新が遅くなり、容量も増えます。

## ポイント

- RDB はデータを表で表し、主キーと外部キーで表をつなぐ
- 制約で、正しくないデータを入れさせない
- 正規化で重複と矛盾をなくす
- まとめて成功させたい更新はトランザクションにする

> **確認しよう**
>
> - 「受注」と「顧客」の表を作るとき、主キーと外部キーはどの列にしますか。
> - 振込の 2 つの更新をトランザクションにしないと、どんな問題が起きるでしょうか。
