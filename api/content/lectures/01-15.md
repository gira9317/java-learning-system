## まずはここから

アルゴリズムは、難しい数式の名前ではなく『問題を解く手順』です。料理のレシピや、名前の一覧から1人を探す順番も例になります。まずは手でできる手順を、順番に説明してみましょう。

### 最初に覚える4つの言葉

#### アルゴリズム

目的を達成するための手順。

**具体例：** 合計を0にし、金額を順番に足す。

#### 探索

目的のデータを探すこと。

**具体例：** 名簿から田中さんを探す。

#### 並べ替え（ソート）

決めた順にデータを並べること。

**具体例：** 点数を高い順に並べる。

#### 最大値

複数の値の中で最も大きい値。

**具体例：** 3・8・2の中から8を選ぶ。

### この講義の読み方

まず上の意味と具体例を確認し、下の4択に挑戦しましょう。詳しい仕組みやコードは「詳しい説明」、発展した内容は「Option」で後から読めます。1回で全てを暗記する必要はありません。

## アルゴリズムとは

問題を解くための **手順** です。料理のレシピのように、誰が実行しても同じ結果になるよう、あいまいさなく書かれている必要があります。

良いアルゴリズムの条件:

- 必ず終わる（有限の手順で止まる）
- 正しい答えを出す
- できるだけ少ない手間（時間・メモリ）で済む

## 代表的なアルゴリズム

### 合計と平均

```java
int sum = 0;
for (int s : scores) {
    sum += s;
}
double avg = (double) sum / scores.length;
```

### 最大値を探す

先頭を仮の最大値とし、それより大きい値が見つかったら入れ替えます。

```java
int max = scores[0];
for (int s : scores) {
    if (s > max) {
        max = s;
    }
}
```

### 線形探索

先頭から順番に調べ、見つかったら止めます。

```java
int index = -1;
for (int i = 0; i < data.length; i++) {
    if (data[i] == target) {
        index = i;
        break;
    }
}
```

### 二分探索

**並べ替え済み** のデータで、真ん中と比べて探す範囲を半分ずつに絞ります。

```java
int low = 0, high = data.length - 1;
while (low <= high) {
    int mid = (low + high) / 2;
    if (data[mid] == target) return mid;
    if (data[mid] < target) low = mid + 1;
    else high = mid - 1;
}
return -1;
```

### バブルソート

隣どうしを比べて、順番が逆なら入れ替えることを繰り返します。

```java
for (int i = 0; i < a.length - 1; i++) {
    for (int j = 0; j < a.length - 1 - i; j++) {
        if (a[j] > a[j + 1]) {
            int tmp = a[j];
            a[j] = a[j + 1];
            a[j + 1] = tmp;
        }
    }
}
```

## 計算量

データの量 n が増えたとき、処理の手間がどれくらい増えるかを **O 記法** で表します。

| 計算量 | 例 | n = 1,000 のときの目安 |
|---|---|---|
| O(1) | 配列の添字で取り出す | 1 |
| O(log n) | 二分探索 | 約 10 |
| O(n) | 線形探索、合計 | 1,000 |
| O(n log n) | 効率の良いソート | 約 10,000 |
| O(n²) | バブルソート | 1,000,000 |

実務では、ソートなどは自分で書かず `Arrays.sort` や `Collections.sort` を使います。ただし、仕組みと計算量を知っておくと、遅い処理の原因に気づけます。

## ポイント

- アルゴリズムは、あいまいさのない有限の手順
- 最大値・探索・ソートは、順次・分岐・反復の組み合わせで書ける
- 二分探索は並べ替え済みのデータでしか使えない
- データが増えたときの手間（計算量）を意識する

## Option：計算量と実測を組み合わせる

O記法は入力が増えたときの伸び方を示しますが、定数倍やメモリ配置までは表しません。少量のデータでは単純な処理が速い場合もあります。

**やってみよう：** 100件・1万件・100万件で探索時間を測り、ソート時間も含めた比較をしてみましょう。
