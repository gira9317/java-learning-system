## まずはここから

メールは、送る仕組みと受け取った内容を読む仕組みが分かれています。郵便を出す窓口と、自分の郵便受けから取り出す場面を分けて考えましょう。名前はまず役割とセットで覚えます。

### 最初に覚える4つの言葉

#### SMTP

メールの送信・転送に使う仕組み。

**具体例：** 作ったメールを配送へ渡す。

#### IMAP

サーバー上のメール状態を扱う仕組み。

**具体例：** 複数端末で既読等をそろえる。

#### POP3

主に受信メールを取り出す仕組み。

**具体例：** メールを端末へ取得する。

#### 添付ファイル

メールに付ける別のファイル。

**具体例：** 資料のPDFを一緒に送る。

### この講義の読み方

まず上の意味と具体例を確認し、下の4択に挑戦しましょう。詳しい仕組みやコードは「詳しい説明」、発展した内容は「Option」で後から読めます。1回で全てを暗記する必要はありません。

## 電子メールの仕組み

メールは、送信と受信で別のプロトコルを使います。

```text
送信者の PC ──SMTP──→ 送信者のメールサーバー ──SMTP──→ 受信者のメールサーバー
                                                          │（メールボックスに保存）
受信者の PC ←──────────── POP3 / IMAP ──────────────────────┘
```

| プロトコル | 役割 | ポート（暗号化なし / 暗号化あり） |
|---|---|---|
| SMTP | メールを **送る**（PC → サーバー、サーバー → サーバー） | 25（サーバー間）、587（PC からの送信・STARTTLS）/ 465（SMTPS） |
| POP3 | サーバーからメールを **受け取る** | 110 / 995（POP3S） |
| IMAP | サーバー上のメールを **閲覧・管理する** | 143 / 993（IMAPS） |

宛先のメールサーバーは、DNS の **MX レコード** で調べます（第 2 章「DNS」）。

## SMTP

メールを送るためのプロトコルです。テキストのコマンドでやりとりします。

```text
クライアント: EHLO client.example.com
サーバー:     250 OK
クライアント: MAIL FROM:<sato@example.com>
サーバー:     250 OK
クライアント: RCPT TO:<yamada@example.jp>
サーバー:     250 OK
クライアント: DATA
サーバー:     354 本文を送ってください
クライアント: Subject: 会議の件
クライアント: （本文）
クライアント: .
サーバー:     250 受け付けました
クライアント: QUIT
```

もともとの SMTP には送信者の確認がないため、今は次の仕組みと組み合わせます。

- **SMTP 認証（SMTP AUTH）**: 送信前に、ユーザー名とパスワードで認証する
- **STARTTLS / SMTPS**: 通信を暗号化する
- **SPF・DKIM・DMARC**: 送信元のドメインが正しいかを確かめる（第 5 章「なりすましメール」）

## POP3 と IMAP

| | POP3 | IMAP |
|---|---|---|
| メールの置き場所 | PC にダウンロードする（サーバーから消すのが基本） | サーバーに置いたまま |
| 複数の端末 | 端末ごとに状態がばらばら | 既読・フォルダが全端末で同じ |
| オフライン | ダウンロード済みなら読める | 基本はサーバーに接続して読む |
| 主な用途 | 1 台の PC でメールを読む | PC・スマホなど複数の端末で読む |

現在は、複数の端末で使うことが多いため IMAP が主流です。

## アプリケーションからメールを送る

業務システムでは、パスワード再設定の案内や通知メールを送ることがあります。Java では Jakarta Mail（旧 JavaMail）などを使い、社内やクラウドのメール送信サービスの SMTP サーバー経由で送ります。

```java
Properties props = new Properties();
props.put("mail.smtp.host", "smtp.example.com");
props.put("mail.smtp.port", "587");
props.put("mail.smtp.auth", "true");
props.put("mail.smtp.starttls.enable", "true");
```

- 認証情報はソースコードに書かず、設定や環境変数で管理する
- テスト中に本物の宛先へ送らないよう、開発用のメールサーバー（受け取ったメールを画面で確認するツール）を使う

## ポイント

- 送信は SMTP、受信は POP3 か IMAP
- 宛先のサーバーは DNS の MX レコードで決まる
- 今は認証と暗号化（587 / 465 / 995 / 993）を使う
- 複数の端末で使うなら IMAP

## Option：非同期配送を前提に設計する

メールは処理の成功後にも遅延や失敗が発生します。アプリの重要データの保存と、メール送信状態を分けて記録すると再送や調査がしやすくなります。

**やってみよう：** 通知メールだけが失敗した場合に、登録そのものを失敗とするかどうか、業務の要求から考えてみましょう。
