title: 証明書
---

## なぜ証明書が必要か

公開鍵暗号では、相手の公開鍵で暗号化すれば、相手にしか読めません（第 1 章「暗号化・復号」）。しかし、その公開鍵が **本当にその相手のものか** はわかりません。攻撃者が自分の公開鍵を「銀行の公開鍵です」と偽って渡すと、通信を盗み見られてしまいます。

**デジタル証明書** は、「この公開鍵は、確かにこの持ち主のもの」と、信頼できる第三者が保証するものです。

## 認証局（CA）とサーバー証明書

**認証局（CA）** は、申請者の身元やドメインの所有を確認し、証明書に **デジタル署名** をして発行します。

サーバー証明書に含まれる主な情報:

| 項目 | 内容 |
|---|---|
| 主体者（サブジェクト） | 証明する相手のドメイン名（例: `www.example.com`） |
| 公開鍵 | そのサーバーの公開鍵 |
| 発行者 | 署名した認証局 |
| 有効期間 | いつからいつまで有効か |
| 署名 | 認証局の秘密鍵による署名 |

証明書の形式は **X.509** という規格で決められています。

## 信頼の連鎖

ブラウザや OS には、信頼できる **ルート認証局** の証明書が、最初から組み込まれています。

```text
ルート認証局（ブラウザ・OS に組み込み済み）
   └ 署名 → 中間認証局の証明書
               └ 署名 → www.example.com のサーバー証明書
```

ブラウザは、サーバー証明書から順に署名をたどり、組み込み済みのルート認証局に行き着けば「信頼できる」と判断します。

## ブラウザが確かめること

1. 信頼できる認証局までたどれるか
2. 有効期間内か
3. 証明書のドメイン名が、アクセスした URL と一致するか
4. 失効（取り消し）していないか

どれかに問題があると、「この接続ではプライバシーが保護されません」などの **警告** が出ます。業務で警告を無視して先に進む癖をつけるのは危険です。

## 証明書の種類（確認のレベル）

| 種類 | 認証局が確認すること |
|---|---|
| DV（ドメイン認証） | ドメインを管理していること |
| OV（組織認証） | 上に加え、組織が実在すること |
| EV（拡張認証） | さらに厳しい審査 |

Let's Encrypt のように、DV 証明書を無料で自動発行するサービスもあります。

## 開発・運用での注意

- **有効期限切れ** はよくある障害。期限を監視し、自動更新の仕組みを作る
- **秘密鍵** は厳重に管理する。漏れたら、証明書を失効させて作り直す
- 開発用の **自己署名証明書** は、どの認証局も保証していないため警告が出る。本番では使わない
- Java のプログラムから HTTPS で接続するとき、エラーを消すために **証明書の検証を無効にしない**。それでは盗み見を防げなくなる

## ポイント

- 証明書は「この公開鍵はこの持ち主のもの」と認証局が保証するもの
- ブラウザはルート認証局までの署名をたどって信頼を確かめる
- 警告を無視しない。期限と秘密鍵を管理する

> **確認しよう**
>
> - ブラウザの鍵のアイコンから、このサイトの証明書の発行者と有効期限を確認してみましょう。
> - 証明書の検証を無効にした Java のプログラムに、どんな危険があるでしょうか。
