## TLS とは

**Transport Layer Security** の略で、TCP の上で通信を暗号化し、安全にするためのプロトコルです。以前は **SSL** と呼ばれていたため、今でも「SSL」「SSL/TLS」と呼ばれることがあります。HTTP を TLS で守ったものが **HTTPS** です。

## TLS が守るもの

| 守るもの | 内容 | 使う技術 |
|---|---|---|
| 機密性 | 盗み見されない | 共通鍵暗号 |
| 完全性 | 途中で改ざんされない | メッセージ認証（MAC） |
| 真正性 | 通信相手が本物である | 証明書と署名 |

## 接続の流れ（ハンドシェイク）

```text
1. クライアント → サーバー: 対応している TLS のバージョンや暗号方式を伝える
2. サーバー → クライアント: 使う方式を決め、サーバー証明書を送る
3. クライアント: 証明書を検証する（信頼できる認証局か、ドメイン名は合っているか）
4. 双方: 鍵交換で、この通信だけで使う共通鍵を安全に作る
5. 以降: その共通鍵でデータを暗号化してやりとりする
```

公開鍵暗号（安全な鍵の共有と相手の確認）と、共通鍵暗号（速いデータの暗号化）を組み合わせた **ハイブリッド方式** です。

## バージョン

| バージョン | 状況 |
|---|---|
| SSL 2.0 / 3.0 | 脆弱性があり、使ってはいけない |
| TLS 1.0 / 1.1 | 古く、主要なブラウザで無効化されている |
| TLS 1.2 | 現在も広く使われる |
| TLS 1.3 | 最新。より速く、安全 |

サーバーでは、古いバージョンや弱い暗号方式を無効にします。

## HTTPS にするときのポイント

- **すべてのページを HTTPS にする**: ログイン画面だけでなく、ログイン後の画面も（セッションの Cookie を守るため）
- **HTTP へのアクセスは HTTPS にリダイレクト** する
- **HSTS**（`Strict-Transport-Security` ヘッダー）で、ブラウザに「このサイトは常に HTTPS で開く」と覚えさせる
- Cookie に `Secure` を付ける
- HTTPS のページの中で、HTTP の画像やスクリプトを読み込まない（**混在コンテンツ**）

## TLS が守らないもの

TLS は **通信の途中** を守る仕組みです。次のものは守れません。

- サーバーに保存されたデータ（DB の暗号化、アクセス制御が必要）
- アプリケーションの脆弱性（SQL インジェクションなど）
- 偽サイトそのもの（偽サイトでも、自分のドメインの正しい証明書は取れる。URL をよく確認する）

「鍵のアイコンがある = 安全なサイト」ではなく、「**そのドメインとの通信が暗号化されている**」という意味です。

## サーバー間の通信も暗号化する

ブラウザとサーバーの間だけでなく、アプリケーションと DB、システムとシステムの間の通信も、可能な限り TLS で暗号化します。

## ポイント

- TLS は通信の機密性・完全性・真正性を守る。HTTPS は HTTP + TLS
- 証明書で相手を確かめ、共通鍵で速く暗号化する
- 古い SSL / TLS は使わない。サイト全体を HTTPS にする
- TLS は通信の途中だけを守る

> **確認しよう**
>
> - ログイン画面だけ HTTPS で、ログイン後の画面が HTTP だと、何が盗まれるおそれがあるでしょうか。
> - 「鍵のアイコンがあるから安全なサイト」と言えないのはなぜでしょうか。
