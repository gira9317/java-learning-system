## まずはここから

条件によって進む道を変えるのが分岐です。『雨なら傘を持つ、雨でなければ持たない』を、プログラムで書くイメージです。難しい条件は後にして、まず2つの道を考えます。

### 最初に覚える4つの言葉

#### if

条件が成り立つときの処理を書く仕組み。

**具体例：** 雨なら傘を持つ処理をする。

#### else

ifの条件が成り立たないときの処理。

**具体例：** 雨でなければ別の処理をする。

#### 条件式

成り立つかどうかを調べる式。

**具体例：** score>=60で点数を確認する。

#### 分岐

条件に応じて処理を分けること。

**具体例：** 合格と不合格で表示を変える。

### この講義の読み方

まず上の意味と具体例を確認し、下の4択に挑戦しましょう。詳しい仕組みやコードは「詳しい説明」、発展した内容は「Option」で後から読めます。1回で全てを暗記する必要はありません。

## 分岐処理とは

条件によって、実行する処理を切り替える流れです。フローチャートでは **ひし形** で表し、ひし形から出る矢印に「True（はい）」「False（いいえ）」を書きます。

```text
       ◇ score >= 60 ?
    True ↙       ↘ False
 [「合格」を表示] [「不合格」を表示]
          ↘     ↙
           [終了]
```

## if 文

```java
if (score >= 60) {
    System.out.println("合格");
} else {
    System.out.println("不合格");
}
```

- 条件式は `true` / `false` になる式
- `else` は省略できる（条件に合わないときは何もしない）

## 3 つ以上に分ける（else if）

```java
if (score >= 80) {
    System.out.println("A");
} else if (score >= 60) {
    System.out.println("B");
} else {
    System.out.println("C");
}
```

条件は **上から順に** 調べられ、最初に当てはまったものだけが実行されます。範囲の広い条件を先に書くと、下の条件に届かなくなるので、順番に注意します。

## switch 文

1 つの値が「どれに等しいか」で分ける場合は、`switch` が読みやすくなります。

```java
switch (day) {
    case "土", "日" -> System.out.println("休日");
    case "月", "火", "水", "木", "金" -> System.out.println("平日");
    default -> System.out.println("不正な曜日");
}
```

（`->` を使う書き方は Java 14 以降。古い書き方の `case ...:` では、各 case の最後に `break;` が必要です。）

## 入れ子（ネスト）

分岐の中に分岐を書けますが、深くなると読みにくくなります。

```java
// 読みにくい
if (user != null) {
    if (user.isActive()) {
        if (user.isAdmin()) {
            showAdminMenu();
        }
    }
}

// 早めに抜ける（ガード節）と読みやすい
if (user == null || !user.isActive()) {
    return;
}
if (user.isAdmin()) {
    showAdminMenu();
}
```

## ポイント

- 分岐はひし形で、出口の矢印に True / False を書く
- `else if` は上から順に判定され、最初に当てはまったものだけ実行される
- 等しいかどうかで分けるなら `switch`
- ネストが深くなったら、条件を整理して早めに抜ける

#### 選択肢

- A. 分岐

正解: D

### 問5【応用】

if(score>=60)でscoreが50なら、elseがあればどちらへ進む？

#### 選択肢

- A. どちらにも進めない
- B. else側
- C. 必ず両方
- D. if側だけ

#### 解答・解説

正解: B

50は60以上ではないので、条件がfalseとなりelse側へ進みます。

## Option：判定表で漏れと重複を探す

条件が増えたら、条件と結果を表にして全ケースを確認します。分岐が多いこと自体より、同時に成り立つ条件の優先順位や、どれにも当てはまらないケースが問題になります。

**やってみよう：** 会員区分と購入金額による割引を表にし、両方の条件が成り立つ場合のルールを決めてみましょう。
