## まずはここから

会社の共有フォルダは、複数の人が同じ場所のファイルを使う仕組みです。便利ですが、誰でも自由に書き換えられると、誤削除や上書きも起こります。見てよい人と変更してよい人を分けましょう。

### 最初に覚える4つの言葉

#### ファイル共有

複数の利用者が同じファイル等を使う仕組み。

**具体例：** 社内の共有フォルダを開く。

#### SMB

Windows等のファイル共有で使う方式。

**具体例：** fileserverの共有フォルダへ接続する。

#### 読み取り権限

内容を見る操作の許可。

**具体例：** 資料を読めるが変更はできない。

#### 書き込み権限

追加や変更等をする許可。

**具体例：** 担当者が共有資料を更新する。

### この講義の読み方

まず上の意味と具体例を確認し、下の4択に挑戦しましょう。詳しい仕組みやコードは「詳しい説明」、発展した内容は「Option」で後から読めます。1回で全てを暗記する必要はありません。

## ファイル共有のプロトコル

ネットワーク上の別のコンピューターにあるファイルを、**自分の PC のフォルダと同じように** 開いたり保存したりする仕組みです。FTP のように「ファイルを送る・受け取る」のではなく、離れた場所のファイルを直接読み書きします。

| プロトコル | 主な環境 | 例 |
|---|---|---|
| SMB（CIFS） | Windows | 社内の共有フォルダ（`\\fileserver\share`） |
| NFS | Linux / UNIX | サーバー間で共有するディレクトリ |

## SMB

Windows のファイル共有で使われるプロトコルです。プリンターの共有にも使われます。

- ポート 445（TCP）を使う
- Windows の「ネットワークドライブの割り当て」や、エクスプローラーで `\\サーバー名\共有名` を開くと使われる
- Linux や macOS でも、Samba などのソフトで SMB の共有を提供・利用できる
- 共有フォルダごとに、ユーザーやグループの **アクセス権** を設定する

```bat
rem 共有フォルダを Z ドライブに割り当てる
net use Z: \\fileserver\share
```

### バージョンと安全性

| バージョン | 状況 |
|---|---|
| SMB1 | 古く、深刻な脆弱性がある（大規模なランサムウェアの感染にも悪用された）。無効にする |
| SMB2 / SMB3 | 現在の標準。SMB3 は通信の暗号化にも対応する |

SMB のポートを、インターネットに公開してはいけません。

## NFS

UNIX / Linux のサーバー間で、ディレクトリを共有するプロトコルです。

```text
# サーバー側: 共有するディレクトリと、許可するクライアントを設定する（/etc/exports）
/export/data  192.168.1.0/24(rw,sync)

# クライアント側: 共有をマウントする
mount -t nfs fileserver:/export/data /mnt/data
```

- 複数のアプリケーションサーバーから、同じファイル（アップロードされたファイルなど）を参照したいときに使われる
- 古いバージョン（NFSv3 まで）は、アクセスを主にクライアントの IP アドレスで制限する。NFSv4 では Kerberos による認証や暗号化も使える

## ファイル共有を使うときの注意

- **アクセス権は最小限に**: 「全員が読み書きできる」共有は、誤操作やランサムウェアの被害を広げる
- **同時に書き込まない工夫**: 複数の人やプログラムが同じファイルを同時に更新すると、内容が壊れることがある
- **ネットワークが切れることを考える**: プログラムからファイル共有を使う場合、接続が切れたときのエラー処理を書く
- **バックアップを取る**

## ほかの共有方法との使い分け

| 方法 | 向いている場面 |
|---|---|
| SMB / NFS | 社内やサーバー間で、ファイルをフォルダとして共有する |
| SFTP | システム間で、決まったファイルを受け渡す |
| クラウドストレージ（S3 など） | インターネット経由で、大量のファイルを保存・配信する |
| データベース | 検索・更新が多い構造化データ |

## ポイント

- SMB は Windows、NFS は Linux / UNIX のファイル共有
- 離れた場所のファイルを、自分のフォルダのように読み書きできる
- SMB1 は使わない。共有をインターネットに公開しない
- アクセス権は最小限に設定する

#### 選択肢

- A. 必要な人に必要な範囲だけ付ける

誤削除や不正変更の影響を減らすため、必要な範囲へ限定します。

## Option：共有をバックアップと取り違えない

複数PCから見えることやRAID構成であることは、誤削除や不正な暗号化から復旧できる保証ではありません。履歴、別領域へのバックアップ、実際の復元確認を組み合わせます。

**やってみよう：** ファイルを誤って上書きした場合、誰がどの時点のデータへ戻せるかを確認してみましょう。
