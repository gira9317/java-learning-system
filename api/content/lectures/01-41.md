## まずはここから

コードを実行しなくても、書き方から間違いの候補を探せる道具があります。それが静的解析です。人の代わりに全て判断する道具ではなく、見落としを減らすチェック係と考えましょう。

### 最初に覚える4つの言葉

#### 静的解析

実行せずコード等から問題の候補を探すこと。

**具体例：** 危険な書き方を機械で調べる。

#### SpotBugs

Java等の問題候補を探す静的解析ツール。

**具体例：** null参照などの可能性を調べる。

#### 警告

確認が必要かもしれないという指摘。

**具体例：** 怪しい箇所の説明を表示する。

#### 誤検知

実際には問題でない箇所への指摘。

**具体例：** 前提を知らない道具が安全な処理も疑う。

### この講義の読み方

まず上の意味と具体例を確認し、下の4択に挑戦しましょう。詳しい仕組みやコードは「詳しい説明」、発展した内容は「Option」で後から読めます。1回で全てを暗記する必要はありません。

## 静的解析とは

プログラムを **実行せずに**、ソースコードやコンパイル結果を調べて、不具合になりそうな箇所を見つけることです。テストでは通らない経路の問題や、人が見落としやすい誤りを機械的に見つけられます。

## FindBugs と SpotBugs

**FindBugs** は、Java のコンパイル済みクラス（バイトコード）を解析して、不具合のパターンを見つけるツールです。開発が止まったあと、後継として **SpotBugs** が開発・保守されています。**現在は SpotBugs を使います**。

## 見つけられる問題の例

| 分類 | 例 |
|---|---|
| 正しさ（Correctness） | 必ず `null` になる変数のメソッド呼び出し、意味のない比較 |
| 悪い習慣（Bad practice） | `equals` をオーバーライドしたのに `hashCode` をしていない、例外を握りつぶしている |
| パフォーマンス | ループの中での文字列の `+` 連結、不要なオブジェクトの生成 |
| マルチスレッド | 同期の不整合 |
| セキュリティ | SQL インジェクションの危険（プラグイン FindSecBugs を追加） |

```java
// SpotBugs が指摘する例: 文字列を == で比較している
if (status == "done") { ... }      // ES_COMPARING_STRINGS_WITH_EQ

// null になりうる値を確認せずに使っている
String name = map.get(key);
return name.length();              // NP_NULL_ON_SOME_PATH の可能性
```

## 使い方

### IDE のプラグイン

IntelliJ IDEA や Eclipse に SpotBugs のプラグインを入れると、エディタ上で解析結果を確認できます。

### ビルドツールに組み込む（Maven の例）

```xml
<plugin>
  <groupId>com.github.spotbugs</groupId>
  <artifactId>spotbugs-maven-plugin</artifactId>
  <version>（最新版を確認して指定）</version>
</plugin>
```

```bat
mvn compile spotbugs:check
```

ビルドや CI（自動ビルド）に組み込んでおくと、問題のあるコードがマージされる前に気づけます。

## 指摘の扱い方

- 指摘には **ランク（重要度）** と **確信度** がある。重要度の高いものから確認する
- 指摘がすべて本当の不具合とは限らない（**誤検知**）。内容を理解してから判断する
- 誤検知と判断したものは、理由を残したうえで除外設定（フィルター）に追加する
- 指摘を黙らせるためだけに、コードをわかりにくく書き換えない

## ほかの静的解析ツール

| ツール | 主な役割 |
|---|---|
| Checkstyle | コーディング規約（書き方）のチェック |
| PMD | 不要なコード、複雑すぎるコードの検出 |
| SonarQube | 上記をまとめて継続的に品質を管理する |
| IDE の警告 | 未使用の変数、null の可能性など |

## ポイント

- 静的解析は、実行せずに不具合の芽を見つける
- FindBugs の後継は SpotBugs
- ビルドに組み込み、重要度の高い指摘から対応する
- 誤検知もあるので、理解してから判断する

### 問5【応用】

警告が出たらどうする？

#### 選択肢

- A. 絶対に直してはいけない

本当の問題か、前提を踏まえて確かめます。警告ゼロだけが目的ではありません。

## Option：品質チェックを段階に分ける

構文・型チェック、静的解析、単体テスト、結合テストは、それぞれ違う種類の問題を見つけます。速い確認から実行し、失敗時に何を直すべきか分かるようにすると開発の待ち時間を減らせます。

**やってみよう：** 自分の変更で起こりそうな不具合を、どのチェックで検出するか分類してみましょう。
