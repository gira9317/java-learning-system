## REST とは

**REpresentational State Transfer** の略で、Web API を設計するときの考え方です。扱う対象を **リソース** として URL で表し、操作を **HTTP メソッド** で表します。REST の考え方に沿った API を **RESTful API** と呼びます。

## リソースと URL

URL には「何を」（名詞）を書き、「どうする」（動詞）は HTTP メソッドで表します。

| 操作 | メソッドと URL | ステータスコード（成功時） |
|---|---|---|
| 社員の一覧を取得 | `GET /employees` | 200 |
| 社員 1 人を取得 | `GET /employees/42` | 200 |
| 社員を登録 | `POST /employees` | 201（`Location: /employees/42`） |
| 社員の情報を置き換え | `PUT /employees/42` | 200 または 204 |
| 社員の情報を一部変更 | `PATCH /employees/42` | 200 |
| 社員を削除 | `DELETE /employees/42` | 204 |
| 社員のスキル一覧 | `GET /employees/42/skills` | 200 |

避けたい URL の例:

| 避けたい例 | 理由 | REST らしい例 |
|---|---|---|
| `GET /getEmployees` | 動詞はメソッドで表す | `GET /employees` |
| `POST /deleteEmployee?id=42` | 削除は DELETE | `DELETE /employees/42` |
| `GET /employee_list.do` | 実装の都合を URL に出さない | `GET /employees` |

## REST の主な原則

| 原則 | 内容 |
|---|---|
| クライアント・サーバー | 画面とデータの処理を分ける |
| ステートレス | 1 つのリクエストに、処理に必要な情報をすべて含める。サーバーはクライアントの状態を持たない |
| 統一されたインターフェース | URL でリソースを識別し、HTTP メソッドで操作する |
| キャッシュ可能 | レスポンスがキャッシュしてよいかを明示する |

## データの形式

現在の Web API では、JSON が最もよく使われます。

```http
GET /employees/42 HTTP/1.1
Accept: application/json
```

```http
HTTP/1.1 200 OK
Content-Type: application/json

{"id": 42, "name": "山田", "dept": "dev"}
```

エラーのときも、ステータスコードと、原因がわかる JSON を返します。

```http
HTTP/1.1 400 Bad Request
Content-Type: application/json

{"message": "入力内容が正しくありません", "fieldErrors": {"name": ["氏名を入力してください"]}}
```

## 一覧の絞り込み・ページ分け

条件はクエリ文字列で渡します。

```text
GET /employees?dept=dev&sort=name&page=2&size=20
```

## このシステムの API

この学習システムも REST の考え方で作られています。例えば:

- `GET /lessons` … 自分の進捗つきのレッスン一覧
- `POST /lessons/3/submissions` … レッスン 3 にフロー図やコードを提出
- `POST /admin/submissions/{id}/approve` … 提出を承認（操作を表すサブリソースとして URL にしている）

すべてを厳密な REST にできない場合もあり、「承認」のような操作は、このように URL で表すこともよくあります。大切なのは、**チームの中で一貫したルール** で設計することです。

## ポイント

- URL は名詞（リソース）、操作は HTTP メソッド
- 結果はステータスコードで返し、エラーも JSON で原因を返す
- ステートレスにする。認証情報も毎回のリクエストで送る（Cookie やトークン）

>
> - 「部署 3 に所属する社員の一覧を取得する」API の URL を考えてみましょう。
> - 「社員 42 のパスワードをリセットする」操作を、どんなメソッドと URL にしますか。
