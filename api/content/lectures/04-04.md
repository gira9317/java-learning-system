## 副問い合わせとは

SQL の中に入れた、もう 1 つの `SELECT` です。**サブクエリ** ともいいます。ある検索の結果を、別の検索の条件や表として使えます。

## WHERE の中で使う

### 1 つの値を返す

```sql
-- 平均給与より高い社員
SELECT name, salary
FROM employees
WHERE salary > (SELECT AVG(salary) FROM employees);
```

括弧の中が先に実行されて平均給与が求まり、その値で外側の検索をします。

### 複数の値を返す（IN）

```sql
-- 開発部・営業部に所属する社員
SELECT name
FROM employees
WHERE dept_id IN (
  SELECT id FROM departments WHERE name IN ('開発部', '営業部')
);
```

`NOT IN` を使うときは、副問い合わせの結果に `NULL` が含まれると、1 件も返らなくなる点に注意します。

## EXISTS

副問い合わせの結果が **1 件でもあるかどうか** を調べます。

```sql
-- 1 件でも提出がある社員
SELECT e.name
FROM employees e
WHERE EXISTS (
  SELECT 1 FROM submissions s WHERE s.user_id = e.id
);

-- 提出が 1 件もない社員
SELECT e.name
FROM employees e
WHERE NOT EXISTS (
  SELECT 1 FROM submissions s WHERE s.user_id = e.id
);
```

このように、外側の行（`e.id`）を参照する副問い合わせを **相関副問い合わせ** といいます。外側の行ごとに評価されます。

## FROM の中で使う（インラインビュー）

副問い合わせの結果を、1 つの表として扱えます。

```sql
-- 部署ごとの平均給与のうち、最も高い値
SELECT MAX(avg_salary)
FROM (
  SELECT dept_id, AVG(salary) AS avg_salary
  FROM employees
  GROUP BY dept_id
) AS dept_avg;
```

## SELECT の中で使う

```sql
-- 社員ごとに、提出の件数を出す
SELECT e.name,
       (SELECT COUNT(*) FROM submissions s WHERE s.user_id = e.id) AS submission_count
FROM employees e;
```

## WITH 句（CTE）

副問い合わせに名前を付けて、先に書けます。複雑な SQL を読みやすくできます。

```sql
WITH dept_avg AS (
  SELECT dept_id, AVG(salary) AS avg_salary
  FROM employees
  GROUP BY dept_id
)
SELECT e.name, e.salary, a.avg_salary
FROM employees e
JOIN dept_avg a ON a.dept_id = e.dept_id
WHERE e.salary > a.avg_salary;   -- 自分の部署の平均より高い社員
```

## JOIN との使い分け

同じ結果を、JOIN でも副問い合わせでも書けることがよくあります。

- **読みやすさ** を優先して選ぶ。「〇〇があるもの」は `EXISTS`、表として組み合わせるなら JOIN が自然なことが多い
- 速さが問題になったら、実行計画（`EXPLAIN`）で確かめてから書き換える

## ポイント

- 副問い合わせは、SQL の中の SQL
- 1 つの値なら比較演算子、複数なら `IN`、有無なら `EXISTS`
- `NOT IN` と `NULL` の組み合わせに注意
- 複雑になったら WITH 句で名前を付ける

> **確認しよう**
>
> - 最も給与の高い社員の氏名を、副問い合わせで求めてみましょう。
> - 講義を 1 つも視聴していない受講者を、`NOT EXISTS` で探す SQL を書いてみましょう。
