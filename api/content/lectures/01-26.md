## まずはここから

プログラムも、作業に使う場所が必要です。メモリはその場所で、動作中の値やデータを置きます。詳しい区分を暗記する前に『置ける量には限りがある』ことから理解しましょう。

### 最初に覚える4つの言葉

#### メモリ

動作中の情報を置く場所。

**具体例：** 開いている処理のデータを覚える。

#### ヒープ

オブジェクト等を置くメモリ領域。

**具体例：** newで作った配列などを置く。

#### スタック

呼び出し中の処理の情報を管理する領域。

**具体例：** メソッドの呼び出しをたどる。

#### GC

到達できなくなった不要なオブジェクト等を回収する仕組み。

**具体例：** 使い終えた領域を再利用できるようにする。

### この講義の読み方

まず上の意味と具体例を確認し、下の4択に挑戦しましょう。詳しい仕組みやコードは「詳しい説明」、発展した内容は「Option」で後から読めます。1回で全てを暗記する必要はありません。

## プログラムが使うメモリ

プログラムを実行すると、OS からメモリが割り当てられ、用途ごとの領域に分けて使われます。Java では、**JVM**（Java 仮想マシン）がこの領域を管理しています。

## Java の主なメモリ領域

| 領域 | 置かれるもの | 特徴 |
|---|---|---|
| スタック | メソッドのローカル変数、引数、呼び出し情報 | スレッドごとにある。メソッドが終わると自動で消える。小さい |
| ヒープ | `new` で作ったオブジェクト、配列 | 全スレッドで共有。ガベージコレクションで回収される。大きい |
| メタスペース | クラスの情報（メソッドの定義など） | クラスを読み込むと使われる |

```java
void sample() {
    int count = 3;                 // count はスタック
    int[] nums = new int[count];   // nums（参照）はスタック、配列の本体はヒープ
    String name = "Java";          // name（参照）はスタック、文字列の本体はヒープ
}
// メソッドが終わると、スタック上の count, nums, name は消える
```

## ガベージコレクション（GC）

どこからも参照されなくなったオブジェクトを、JVM が自動で回収してメモリを空けます。C 言語のように、プログラマーがメモリを手動で解放する必要はありません。

```java
StringBuilder sb = new StringBuilder("a");
sb = new StringBuilder("b"); // 最初の "a" のオブジェクトは誰からも参照されない → GC の対象
```

ただし、GC があってもメモリ不足は起きます。

## よくあるメモリのエラー

| エラー | 原因の例 |
|---|---|
| `StackOverflowError` | 再帰呼び出しが終わらない（スタックを使い切る） |
| `OutOfMemoryError: Java heap space` | 大量のデータを一度に読み込む、使い終わったオブジェクトをリストや static 変数に持ち続ける（メモリリーク） |

```java
static int fact(int n) {
    return n * fact(n - 1); // 終了条件がないため、StackOverflowError
}
```

## ヒープの大きさの指定

JVM の起動オプションで、ヒープの大きさを指定できます。

```bat
java -Xms256m -Xmx1g Main
```

- `-Xms`: 最初に確保する大きさ
- `-Xmx`: 最大の大きさ

## ポイント

- ローカル変数はスタック、`new` したオブジェクトはヒープ
- 参照されなくなったオブジェクトは GC が回収する
- 「使わないのに持ち続ける」とメモリリークになる
- 再帰には必ず終了条件を書く

### 問5【応用】

データを際限なく覚えさせ続けると？

#### 選択肢

- A. メモリ不足になる可能性がある
- B. PCの容量が無限に増える
- C. 問題は絶対に起きない
- D. 必ずメモリが減る

#### 解答・解説

正解: A

置ける量には限りがあります。GCがあっても、保持し続けるデータは自動で不要になりません。

## Option：GCがあってもメモリリークは起こる

Javaでも、使わないデータへの参照をキャッシュやリスナー等が保持し続けると回収されません。ヒープダンプ等で、何がどこから保持されているかを見ることが調査の手掛かりです。

**やってみよう：** 上限なしのキャッシュに、件数制限や有効期限を設ける設計を考えてみましょう。
