## トレースとは

プログラムを **1 行ずつ追いかけて**、変数の値がどう変わるかを確かめることです。机の上で紙に書きながら行う方法（**机上トレース**）と、デバッガーを使って実際に動かしながら行う方法があります。

「思ったとおりに動かない」ときに、どこで考えと違う動きになっているかを見つけるための、基本の技術です。

## 机上トレース

変数ごとの列を作り、1 行実行するたびに値を書きます。

```java
int sum = 0;
for (int i = 1; i <= 4; i++) {
    if (i % 2 == 0) {
        sum += i;
    }
}
System.out.println(sum);
```

| 手順 | i | i <= 4 | i % 2 == 0 | sum |
|---|---|---|---|---|
| 初期 | — | — | — | 0 |
| 1 回目 | 1 | true | false | 0 |
| 2 回目 | 2 | true | true | 2 |
| 3 回目 | 3 | true | false | 2 |
| 4 回目 | 4 | true | true | 6 |
| 終了 | 5 | false | — | 6 |

出力は 6 です。表にすると、ループの回数や境界の間違い（`<` と `<=` など）に気づきやすくなります。

## デバッガーを使ったトレース

IDE（IntelliJ IDEA、Eclipse、VS Code）のデバッガーで、実行を途中で止めて中を見られます。

| 操作 | 内容 |
|---|---|
| ブレークポイント | その行に来たら実行を止める |
| ステップオーバー | 1 行進める（メソッドの中には入らない） |
| ステップイン | 呼び出したメソッドの中に入る |
| ステップアウト | 今のメソッドを最後まで実行して、呼び出し元に戻る |
| 変数の監視 | 止まっている時点の変数の値を見る |
| 条件付きブレークポイント | 条件を満たしたときだけ止める（例: `i == 500`） |

## ログによるトレース

本番環境のようにデバッガーを使えない場所では、**ログ** に処理の流れや値を出して追いかけます。

```java
private static final Logger log = LoggerFactory.getLogger(PayrollService.class);

log.debug("計算開始: employeeId={}, month={}", employeeId, month);
```

- `System.out.println` ではなく、ログ出力のライブラリ（SLF4J + Logback など）を使う
- レベル（ERROR / WARN / INFO / DEBUG）を使い分け、本番では出す量を調整する
- パスワードや個人情報をログに出さない

## スタックトレース

例外が起きたときに表示される、**呼び出しの履歴** です。上から順に「例外が起きた場所」→「それを呼んだ場所」と並んでいます。

```text
Exception in thread "main" java.lang.NullPointerException
    at com.example.Member.getName(Member.java:12)
    at com.example.MemberService.greet(MemberService.java:25)
    at com.example.Main.main(Main.java:8)
```

まず **自分たちのコードの一番上の行**（ここでは `Member.java:12`）を見ます。

## ポイント

- トレースは、変数の値の変化を 1 行ずつ追うこと
- 机上トレースは表にする。デバッガーではブレークポイントとステップ実行を使う
- 本番ではログで追う。スタックトレースは上から読む

> **確認しよう**
>
> - `int x = 1; while (x < 20) { x = x * 3; }` を机上トレースし、最後の `x` を求めてみましょう。
> - デバッガーの「ステップオーバー」と「ステップイン」は、どう使い分けるでしょうか。
