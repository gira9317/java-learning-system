## UML とは

**Unified Modeling Language** の略で、システムの構造や振る舞いを図で表すための、決まった書き方です。設計を言葉だけで伝えるとあいまいになるため、共通の図で表して認識をそろえます。

## よく使う図

| 図 | 表すもの | 使う場面 |
|---|---|---|
| ユースケース図 | 利用者（アクター）とシステムの機能の関係 | 要件定義 |
| アクティビティ図 | 処理や業務の流れ | 業務フロー、処理の流れ |
| クラス図 | クラスの属性・操作と、クラス間の関係 | 設計 |
| シーケンス図 | オブジェクト間のやりとりの順番 | 設計 |
| ステートマシン図 | 状態とその変化 | 状態を持つもの（注文、申請など）の設計 |

## クラス図

クラスを 3 段の箱で表します。

```text
┌──────────────────────┐
│ Employee             │ ← クラス名
├──────────────────────┤
│ - name: String       │ ← 属性
│ - salary: int        │
├──────────────────────┤
│ + raise(amount: int) │ ← 操作
│ + getName(): String  │
└──────────────────────┘
```

| 記号 | 意味 |
|---|---|
| `+` | public |
| `-` | private |
| `#` | protected |

クラス間の関係:

| 関係 | 線 | 意味 | 例 |
|---|---|---|---|
| 関連 | 実線 | 互いを知っている | 社員 — 部署 |
| 集約 | 白いひし形 | 全体と部分（部分は単独でも存在する） | 部署 ◇— 社員 |
| コンポジション | 黒いひし形 | 全体と部分（全体が消えると部分も消える） | 注文 ◆— 注文明細 |
| 汎化（継承） | 白い三角の矢印 | is-a の関係 | 正社員 —▷ 社員 |
| 実現 | 点線と白い三角 | インターフェースの実装 | Circle ┄▷ Shape |
| 依存 | 点線の矢印 | 一時的に使う | Service ┄> Repository |

線の端に **多重度**（`1`、`0..1`、`*`、`1..*`）を書いて、「部署 1 つに社員が何人か」を表します。

## シーケンス図

縦に時間が流れ、オブジェクト間のメッセージ（メソッド呼び出し）を横の矢印で表します。

```text
利用者      Controller      Service        Repository
  │  ログイン   │              │                │
  │──────────→│ login(id,pw) │                │
  │            │────────────→│ findById(id)   │
  │            │              │──────────────→│
  │            │              │←── User ───────│
  │            │←── 結果 ─────│                │
  │←─ 画面 ────│              │                │
```

処理の順番や、どのクラスがどのクラスを呼ぶかを確認するのに向いています。

## アクティビティ図

フローチャートに近い図で、処理の流れや分岐、並行処理を表します。業務の流れを、部署ごとのレーン（スイムレーン）に分けて描くこともできます。

## 図を描くツール

- draw.io（diagrams.net）: 無料で、ブラウザやアプリで描ける
- PlantUML: テキストで書くと図になる。ソースコードと一緒に管理できる

```text
@startuml
class Employee {
  - name: String
  + raise(amount: int)
}
Employee "*" -- "1" Department
@enduml
```

## ポイント

- UML は設計を図で共有するための共通の書き方
- 構造はクラス図、やりとりの順番はシーケンス図、流れはアクティビティ図
- すべての図を描く必要はない。伝えたいことに合った図を選ぶ

> **確認しよう**
>
> - 「注文」と「注文明細」がコンポジションなのはなぜでしょうか。
> - 会員登録の処理（画面 → Controller → Service → Repository）をシーケンス図で描いてみましょう。
