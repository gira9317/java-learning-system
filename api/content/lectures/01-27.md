## まずはここから

人が書くコードを、実行できる形へ変える役割がコンパイラーです。『作るための書き方』と『動かすための形』の間に変換が入ると考えましょう。Javaでは変換と実行を別々に確認できます。

### 最初に覚える4つの言葉

#### コンパイル

ソースを別の実行表現等へ変換すること。

**具体例：** javacでclassファイルを作る。

#### 実行時エラー

プログラムを動かした時に分かる問題。

**具体例：** 存在しない対象を使って例外になる。

#### コンパイルエラー

変換の段階で見つかる問題。

**具体例：** 文末の記号が足りず変換できない。

#### JVM

Javaのバイトコードを実行する環境。

**具体例：** classファイルの指示を動かす。

### この講義の読み方

まず上の意味と具体例を確認し、下の4択に挑戦しましょう。詳しい仕組みやコードは「詳しい説明」、発展した内容は「Option」で後から読めます。1回で全てを暗記する必要はありません。

## 変換して実行する 2 つの方法

人が書いたソースコードを、コンピューターが実行できる形にする方法は大きく 2 つあります。

| 方式 | 仕組み | 例 |
|---|---|---|
| コンパイラー方式 | 実行前に、ソースコード全体を機械語などに **まとめて変換** する | C、Go、Rust |
| インタープリター方式 | 実行しながら、ソースコードを **1 文ずつ解釈** して実行する | Python、Ruby、シェルスクリプト |

## それぞれの特徴

| | コンパイラー方式 | インタープリター方式 |
|---|---|---|
| 実行速度 | 速い | 遅め |
| 実行までの手間 | コンパイルが必要 | すぐ実行できる |
| エラーの発見 | 文法や型の誤りを実行前に見つけられる | その行を実行するまでわからないことがある |
| 配布 | 環境ごとに作った実行ファイルを配る | ソースコードとインタープリターがあれば動く |

## Java は両方の組み合わせ

Java は、まずコンパイラーで **バイトコード**（`.class` ファイル）に変換し、それを **JVM** が実行します。

```text
Main.java ──javac──→ Main.class（バイトコード）──java（JVM）──→ 実行
```

- バイトコードは特定の CPU 用ではないため、JVM があれば Windows でも Linux でも同じ `.class` が動く（Write once, run anywhere）
- JVM は、よく実行される部分を実行中に機械語に変換して速くする（**JIT コンパイル**）

JavaScript や Python も、現在の実行環境の多くは内部でバイトコードや JIT を使っており、2 つの方式の境界はあいまいになっています。

## コンパイルエラーと実行時エラー

- **コンパイルエラー**: 文法や型の誤り。`javac` が見つけ、`.class` は作られない
- **実行時エラー（例外）**: 実行して初めて起きる誤り。0 で割る、配列の範囲外、`null` の利用など

```java
int x = "abc";        // コンパイルエラー
int[] a = new int[3];
a[5] = 1;             // 実行時エラー（ArrayIndexOutOfBoundsException）
```

コンパイルエラーは、メッセージと行番号を読めば多くはすぐ直せます。エラーメッセージは **最初の 1 つ** から順に読みます。

## ポイント

- コンパイラーはまとめて変換、インタープリターは 1 文ずつ実行
- Java はバイトコードにコンパイルし、JVM が実行する
- コンパイルエラーは実行前に、実行時エラーは実行中に見つかる

## Option：バイトコードを見てみる

javapを使うとクラスファイルの情報やバイトコードを確認できます。ソースの1行と実行命令が1対1でないことを知ると、コンパイルと実行の役割を理解しやすくなります。

**やってみよう：** 小さなMainをコンパイルし、`javap -c Main`で条件分岐やメソッド呼び出しを探してみましょう。
