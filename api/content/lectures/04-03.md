## JOIN とは

**複数の表を、関連する列でつないで** 1 つの結果にすることです。正規化で分けた表を、検索のときに組み合わせて使います。

この講義では、次の 2 つの表を使います。

**employees**

| id | name | dept_id |
|---|---|---|
| 1 | 山田 | 10 |
| 2 | 佐藤 | 20 |
| 3 | 鈴木 | NULL |

**departments**

| id | name |
|---|---|
| 10 | 開発部 |
| 20 | 営業部 |
| 30 | 総務部 |

鈴木さんは部署が未定、総務部には社員がいない、という状態です。

## 内部結合（INNER JOIN）

**両方の表に対応する行があるものだけ** を取り出します。

```sql
SELECT e.name, d.name AS dept
FROM employees e
INNER JOIN departments d ON e.dept_id = d.id;
```

| name | dept |
|---|---|
| 山田 | 開発部 |
| 佐藤 | 営業部 |

部署のない鈴木さんと、社員のいない総務部は出てきません。

## 左外部結合（LEFT OUTER JOIN）

**左の表の行はすべて** 残し、右の表に対応する行がなければ `NULL` にします。

```sql
SELECT e.name, d.name AS dept
FROM employees e
LEFT JOIN departments d ON e.dept_id = d.id;
```

| name | dept |
|---|---|
| 山田 | 開発部 |
| 佐藤 | 営業部 |
| 鈴木 | NULL |

「全社員を一覧にし、部署がわかれば部署名も出す」ときに使います。

## 右外部結合・完全外部結合

- **RIGHT JOIN**: 右の表の行をすべて残す（表の順番を入れ替えた LEFT JOIN と同じ）
- **FULL OUTER JOIN**: 両方の表の行をすべて残す

```sql
-- 社員のいない部署を探す
SELECT d.name
FROM departments d
LEFT JOIN employees e ON e.dept_id = d.id
WHERE e.id IS NULL;
```

| name |
|---|
| 総務部 |

「相手がいないもの」を探すときは、外部結合して、相手の列が `NULL` の行に絞ります。

## 3 つ以上の表をつなぐ

```sql
SELECT e.name, d.name AS dept, s.name AS skill
FROM employees e
JOIN departments d     ON e.dept_id = d.id
JOIN employee_skills es ON es.employee_id = e.id
JOIN skills s          ON s.id = es.skill_id;
```

社員とスキルのように「多対多」の関係は、中間の表（`employee_skills`）を使って表します。

## 自己結合

同じ表どうしをつなぎます。上司も社員の 1 人として同じ表にある場合などに使います。

```sql
SELECT e.name, boss.name AS boss
FROM employees e
LEFT JOIN employees boss ON e.boss_id = boss.id;
```

## 注意すること

- **結合の条件（ON）を忘れたり間違えたりすると**、すべての組み合わせ（直積）が出て、件数が爆発的に増える（社員 1,000 人 × 部署 50 で 50,000 行）
- 1 対多の結合では、「1」の側の行が複数回出てくる。そのまま `SUM` すると、合計が多く数えられることがある
- 結合に使う列（外部キー）には、インデックスを作っておくと速くなる

## ポイント

- INNER JOIN は両方にあるものだけ、LEFT JOIN は左の表をすべて残す
- 「相手がいないもの」は外部結合して `IS NULL` で探す
- 多対多は中間の表でつなぐ
- 結合の条件の誤りに注意する

> **確認しよう**
>
> - 全部署について、所属する社員の人数を求める SQL を書いてみましょう（社員のいない部署は 0 人と表示）。
> - INNER JOIN で検索したら、部署が未定の社員が一覧から消えてしまいました。どう直しますか。
