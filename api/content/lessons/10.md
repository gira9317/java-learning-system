## このレッスンの目標

- 例外が発生したときの処理の流れを説明できる
- `try`と`catch`で想定した例外に対応できる
- 入力の事前確認と例外処理を使い分けられる

## 例外とは

数値に変換できない文字列を変換したり、配列の範囲外にアクセスしたりすると、例外が発生します。
対応する処理がなければ、例外は呼び出し元へ伝わり、最終的にプログラムが終了することがあります。

## tryとcatch

```java
public class Main {
    public static void main(String[] args) {
        if (args.length == 0) {
            System.out.println("数値を指定してください");
            return;
        }

        try {
            int number = Integer.parseInt(args[0]);
            System.out.println(number * 2);
        } catch (NumberFormatException e) {
            System.out.println("整数を指定してください");
        }
    }
}
```

引数が`12`なら`24`、`abc`なら`整数を指定してください`と表示します。
例外が発生すると、`try`の残りの処理は実行せず、型が一致する`catch`に移ります。

## 事前確認と例外処理

引数があるかどうかは、`args.length`で事前に確認できます。
文字列を整数に変換できるかどうかは、上の例では`NumberFormatException`で対応しています。
例外を空の`catch`で握りつぶすと、失敗したことが分からなくなるので避けましょう。

## 後片付け

ファイルなど、使い終わったら閉じる必要がある資源には、対応する型であればtry-with-resourcesを使えます。
`finally`は通常、例外の有無にかかわらず実行されますが、JVMの強制終了などでは実行されない場合があります。

## 確認ポイント

- 正常な入力と不正な入力の両方を試しましたか
- 発生し得る具体的な例外の型を指定していますか
- 例外が起きた後に、どの行から処理が続くか説明できますか
