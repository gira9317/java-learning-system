# コード演習の教材

ファイル名は内部のレッスンIDに対応します。画面の番号は学習順です。
`11.md`〜`15.md`は、通常の`01.md`〜`10.md`より前に学ぶ入門編です。
既存のURL・下書き・提出を保つため、内部IDは振り直しません。
先頭のfront matterに、`api/scripts/seed.ts`に登録されたレッスン名と同じ`title`を記載します。

各教材は「目標 → 解説とサンプル → 確認ポイント」を基本にします。
サンプルは概念の説明用です。演習の問題文・提出コード・採点用テストケースとは別に管理します。

`GET /lessons/:id`がMDを直接読み込み、解放済みのレッスンでは`material_md`として返します。
`/lessons/:id`の教材画面で、講義と共通のMarkdown表示を使って描画します。
ファイル未作成の場合は準備中を表示し、タイトル不一致などの設定ミスはAPIエラーとして検出します。

DBへの取り込みは不要です。ローカルではMDの保存後に教材画面を再読み込みすると反映されます。
DockerではAPIイメージに含まれるので、変更後はAPIの再ビルドが必要です。
`npm run content:import`は講義用の`content/lectures/`だけが対象です。

## 演習問題

`exercises.json`に全10レッスン×5問を定義します。配列の順番が問題番号です。
`intro-exercises.json`に入門5レッスン×5問を定義し、`starterBody`で最初に表示するコードを用意します。
`readability-exercises.json`にリファクタリング1レッスン×5問を定義します。全体では16レッスン・80問です。
最初の問題は実行するだけ、以降は1か所ずつ変える段階的な練習です。入門編ではフロー図提出を求めず、コードのみで取り組めます。
リファクタリング演習もコードのみで取り組みます。`starterCode`には複数クラスを含むJava全文を指定でき、`starterBody`より優先されます。改善前も正しく動くコードを渡し、動作の維持は採点、命名・責務・コメントなどの改善はレビューで確認します。
`title`と`prompt`が問題文、`tests`が採点用の引数と期待する出力です。
`hidden: true`のテストはAPIから受講者へ配信しません。
実行結果を比較する自動採点に加え、指定した構文やクラスの使用は担当者がレビューします。

演習画面の`?question=1`〜`5`で問題を切り替えます。
下書き・提出・レビューは問題ごとに独立し、既存データは第1問として保持されます。
新たに学習するレッスンは全5問のコード承認で完了します。既に完了した進捗は維持します。
スキーマ変更には`npm run db:migrate`が必要です。

## 読みやすいコードの演習

「クラスとオブジェクト」の直後に、内部ID16・表示Lesson15として配置しています。
命名、早期リターン、責務分割・コメント、神クラス、メッセージチェーンの5問です。
`16.md`には20種類のアンチパターンと見直し方をまとめ、便利なメソッドチェーンとの違いや、細分化・共通化しすぎる失敗も説明しています。

専用一覧は`/curriculm`です。レッスンを追加した場合は、`web/app/curriculm/page.tsx`の学習段階にもIDを追加します。起動・追加・検証手順の全体は[ルートのREADME](../../../README.md)を参照してください。
