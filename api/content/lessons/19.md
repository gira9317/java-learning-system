## このレッスンの目標

- 標準入力からコマンドを受け取り、状態を持ったプログラムを作れる
- 「入出力」「業務のルール」「データ」を別のクラスに分けられる
- 日付と時刻を `java.time` で正しく扱える
- 仕様の表を読み、エラーのときの表示まで漏れなく作れる

## コマンドを1行ずつ読む

実際の業務システムは、利用者の操作を受け取って、データを更新し、結果を返すことを繰り返します。この演習では、操作を標準入力のコマンドとして受け取ります。

```java
Scanner sc = new Scanner(System.in);
while (sc.hasNextLine()) {
    String line = sc.nextLine().trim();
    if (line.isEmpty()) continue;
    String[] cmd = line.split(" ");
    switch (cmd[0]) {
        case "add" -> System.out.println(library.add(cmd[1], cmd[2]));
        case "list" -> library.list().forEach(System.out::println);
        default -> System.out.println("不明なコマンド: " + cmd[0]);
    }
}
```

実行欄の「標準入力」に1行1コマンドで書いて「実行」すると、上から順に処理されます。「対話」はないので、入力を全部書いてから実行します。

`split(" ", 3)` のように分ける数を決めると、3つ目以降をまとめて受け取れます（タイトルに空白が入るときなど）。

## 役割で分ける

すべてを `Main` に書くと、どこを直せばよいか分かりにくくなります。よく使う分け方は次の3つです。

```
Main.java              … 入力を読み、結果を表示する（画面の役）
library/
  Library.java         … 貸出のルール（業務の役）
  Book.java            … 1冊分のデータ（データの役）
```

- `Main` は「何のコマンドか」を見て、業務のクラスのメソッドを呼ぶだけにする
- ルール（貸出中なら貸せない、など）は業務のクラスに書く
- データのクラスは、自分の状態を変えるメソッドを持ち、外から勝手に書き換えられないようにする（`private` のフィールド）

こう分けておくと、あとで画面を Web にしても、ルールのクラスはそのまま使えます。

## 日付と時刻：java.time

日付や時刻を文字列や数のまま計算すると、繰り上がりや月末で間違えやすくなります。

```java
import java.time.*;

LocalDate date = LocalDate.parse("2026-04-01");
LocalTime in = LocalTime.parse("09:00");
LocalTime out = LocalTime.parse("18:30");
long minutes = Duration.between(in, out).toMinutes();   // 570
boolean late = date.isBefore(LocalDate.parse("2026-04-10"));
String week = date.getDayOfWeek().getDisplayName(TextStyle.SHORT, Locale.JAPANESE); // 水
```

`LocalDate` どうしは `isBefore`・`isAfter`・`equals` で比べ、`Comparator.comparing(Task::getDue)` で並べ替えられます。

## 仕様の表を読む

業務システムでは、うまくいったときより、うまくいかないとき（見つからない・重なっている・足りない）の扱いのほうが多くなります。作り始める前に、仕様の表の各行について「どんな入力のとき、何を表示するか」を確かめましょう。分からないところがあれば、書く前に質問するのも大切な仕事です。

## 確認ポイント

- `Main` に業務のルールを書いていませんか
- エラーのときの表示が、仕様の文言とすべて一致していますか
- 日付・時刻を `java.time` で扱っていますか
- 「定数にすべき数字」（税率・休憩時間など）に名前を付けていますか
