---
title: 継承とインターフェース
---

## このレッスンの目標

- フォルダ（package）とファイルに分けて、クラスを整理できる
- インターフェースで「できること」を決め、クラスごとに中身を変えられる
- 抽象クラスと継承で、共通の部分を1か所にまとめられる
- 種類が増えても、呼び出す側を書き換えずに済む形（ポリモーフィズム）を説明できる

## フォルダは package

応用編では、エディタ左の「ファイル」で `+ フォルダ` を押してフォルダを作り、その中にファイルを作れます。Java ではフォルダが **package**（パッケージ）になります。

```
Main.java
payment/
  PaymentMethod.java
  Cash.java
  CreditCard.java
```

フォルダの中のファイルは、1行目に `package フォルダ名;` を書きます（新しく作ったファイルには最初から入っています）。別の package のクラスを使うときは `import` します。

```java
// payment/Cash.java
package payment;

public class Cash implements PaymentMethod {
    public String name() { return "現金"; }
    public int fee(int amount) { return 0; }
}
```

```java
// Main.java
import payment.Cash;        // 1つだけ使う
import payment.*;           // payment の中を全部使う
```

- package の外から使うクラス・メソッドには `public` を付けます。付けないと、同じ package の中からしか使えません
- フォルダ名は英小文字（`payment`、`model` など）、クラス名は英大文字で始めます

## インターフェース：「できること」の約束

インターフェースは、クラスが持つべきメソッドの**名前と形だけ**を決めたものです。

```java
public interface PaymentMethod {
    String name();
    int fee(int amount);
}

public class CreditCard implements PaymentMethod {
    public String name() { return "カード"; }
    public int fee(int amount) { return amount * 3 / 100; }
}
```

`implements` したクラスは、決められたメソッドを必ず書きます。呼び出す側は、相手が現金かカードかを気にせず、`PaymentMethod` として扱えます。

```java
PaymentMethod method = new CreditCard();
System.out.println(method.fee(1000)); // 30（カードの計算が動く）
```

同じ `method.fee(...)` の呼び出しでも、入っているインスタンスによって動く処理が変わります。これを**ポリモーフィズム**（多態性）と呼びます。支払い方法が増えても、新しいクラスを足すだけで、呼び出す側の `if` を増やさずに済みます。

## 抽象クラスと継承：共通の部分をまとめる

正社員とアルバイトのように、「名前を持つ」などの共通部分があり、給与の計算だけが違うときは、抽象クラスを使います。

```java
public abstract class Employee {
    private final String name;

    protected Employee(String name) { this.name = name; }

    public String getName() { return name; }

    public abstract int monthlyPay(); // 中身は子クラスが決める
}

public class FullTime extends Employee {
    private final int salary;

    public FullTime(String name, int salary) {
        super(name); // 親クラスのコンストラクタを呼ぶ
        this.salary = salary;
    }

    public int monthlyPay() { return salary; }
}
```

- `extends` で親クラスを継承すると、親のフィールドやメソッドを引き継ぎます
- `abstract` のメソッドは、子クラスで必ず書きます。抽象クラスそのものは `new` できません
- 子クラスのコンストラクタでは、最初に `super(...)` で親を初期化します

## どちらを使うか

| | インターフェース | 抽象クラス |
|---|---|---|
| 持てるもの | メソッドの形（と定数） | フィールド・ふつうのメソッドも |
| いくつ付けられるか | 1つのクラスにいくつでも | 親は1つだけ |
| 向いている場面 | 「〜できる」という役割（支払える、通知できる） | 共通のデータや処理があり、一部だけ違う |

迷ったらインターフェースから始め、共通の処理が増えてきたら抽象クラスを考えます。継承を深くしすぎる（親の親の親…）と、どこで何が決まっているか追いにくくなるので注意しましょう。

## 確認ポイント

- 種類ごとの違いを `if` や `switch` で何度も書かず、クラスの中に閉じ込めていますか
- 呼び出す側は、インターフェース（親クラス）の型で受け取っていますか
- フォルダの中のファイルに `package` を書き、外から使うものに `public` を付けていますか
- 新しい種類を足すとき、既存のクラスを書き換えずに済みますか
